### 1.0 底座条：原子写（#2 / #5 共用）

- **为什么**：`Path.write_text` 是"先截断、后写入"。写入过程中任何异常（编码、磁盘满、Ctrl-C）都留下**被清空的假产物**。
  本轮实证：8,003 B → 0 B，且**报错发生在 `f.write()`，文件已经没了**。
- **验收判据**：新 `tests/test_artifact.py` 里做一次"写 1 MB 时抛异常"的注入 → 目标文件**保持原内容**（变异验证：去掉 `os.replace` 后测试必须变红）。
- **参照补丁**：四段式汇总 `E12`/`E13`（命令类）与主报告 A2 的代码块。
- **同族一并收口**：`B03`（`manifest.version` 裸 `int()`）与 `B04`（门禁账本）是**同一坑型**的第一/第二次出现（登记册§3 已裁定：机制记 🟠，两个具体点位 🔴）——
  建议跟 #5 同批用一个 `artifact.load_json()` + `safe_int()` 收口，**不要只修门禁账本**。

### 4.1 现状（实测，来自主报告 §1.1–§1.3）

```
讲稿.md ──parse──▶ parse.json ──shots──▶ shots.json(475 KB) ──assets──▶ assets/{local,graphic}/*.png
                                              │                        └─ cardhtml 无头浏览器截图（P01 无 timeout）
                                              ├─cast──▶ cast lock（定妆）
                                              ├─voice─▶ audio/*.wav + subtitle.srt（缓存键缺参数指纹 F02）
                                              └─build─▶ final.mp4（非原子写 F01）→ publish → 封面/文案
编排：stage 表驱动（Stage vs Driver 两层，已实践）；产品契约：workspace/manifest + gate 账本（非原子写 F03）
```

**已经做对的（不要动）**：stage 表驱动编排、产物契约（manifest/ledger）、`gate` 人审闸门、配置掩码、`publish` 一条命令出全平台物料、`tests/test_architecture.py` 的 25 条结构判据（其中 **24 条经变异确认可红**）。

### 4.2 目标架构（加粗的是本轮建议新增的层）

```
                 ┌────────────────────────── lvs/ ──────────────────────────┐
  用户 / Agent ──▶ cli.py（唯一入口；--json 统一信封）                        │
                     │                                                       │
                     ├─ summary.py   ★新  「我现在在哪」一屏结论（= lvs status --brief）  ← agent 续跑第一步
                     ├─ doctor.py    ★升级 环境体检 → 续跑助手（人话 + JSON）  │
                     │                                                       │
                     ├─ stage.py（Stage 表：每阶段的 输入/产物/门禁/耗时）      │
                     │      └─ 六个 Stage：parse · shots · assets · voice · build · publish
                     │                                                       │
                     ├─ **artifact.py  ★新  唯一写路径：atomic_write_text/bytes**  ← A2，被全部产物复用
                     ├─ **cachekey.py  ★新  唯一复用判据：参数指纹**              ← A3，voice 是第一个用户
                     ├─ **errors.py    ★新  错误分类（FFmpegError 家族 / 用户 / 内部）→ 退出码 + 信封**
                     ├─ media.py      ★新  唯一扩展名白名单（B02/Q02 的 5 份副本收成 1 份）
                     │                                                       │
                     └─ workspace.py（产物契约：manifest + gate 账本，全部走 artifact.py）
```

四条不变量（建议写进 `tests/test_architecture.py`，让它"只降不升"地守住）：

1. **写产物只有一条路**：`lvs/**` 里不允许出现裸 `Path.write_text` / `open(...,'w')` 写产物（例外：`.work/tmp/` 下的调试脚本）。
2. **凡"跳过/复用"必带指纹**：缓存命中前必须比对 `cachekey` 里的参数指纹；没指纹 = 不许命中。
3. **阶段只经 `stage.py` 进入**：现有架构测试已覆盖（唯一存活变异 = `test_orchestrators_go_through_the_stage_table`），建议把它从"存活"变成"可红"（补一条真会拦住的用例）。
4. **错误必须分类后再出 CLI**：`FFmpegError` 家族不允许被泛 `except Exception` 吞掉（B01 的根因）。

### 4.5 一句话架构判据

> **任何"跳过/复用/写产物"的行为，都必须有一个能跑出来的指纹或原子边界**；

> 这两条能同时成立，token 成本和事故率会一起降下来。

## §5 反面清单（**明确不要做**，与四段式汇总 §3 一致）

| 不要做 | 为什么 |
|---|---|
| 不要给渲染/生图/TTS 加并发（`P13`） | 实测 4 线程只有 1.34×（x264 已吃满 20 逻辑线程），代价是内存 ×N、与 GPU 抢核、日志交错 |
| 不要给 `_WHISPER_CACHE` 加 LRU（`P14`） | key 空间 ≤ 4、value 几百 MB 且本该常驻，加 LRU 只会换来几十秒重载 |
| 不要给 `/thumb` 加缓存（`P16`） | 重活已有磁盘缓存，加缓存会破坏"选图后缩略图必刷新" |
| 不要为"单字母变量"开一次改动（`Q14`） | 19 处里只有 2 处真值得改，其余是惯用短名 |
| 不要把 62 处 `except Exception` 全改掉（`Q20`） | 抽样后多数合理；只做"纯吞必须写理由" |
| 不要动 CC 11–20 的 84 个函数（`Q08`） | 复杂度来自业务规则本身，硬拆只会把规则散开 |
| 不要为 78 行超长行改代码（`Q21`） | 配好 `line-length = 120` 即可全绿 |
| 不要按"门禁看不出坏成片"去改门禁（`B00`） | 异常路径已有 `assert_segment_rendered` 兜底；真正缺的是原子写与"失败即删半成品" |
| 不要给"根目录杂物"单独定级（`M13`） | 与 `E04` 是同一件事，只算一条 |
