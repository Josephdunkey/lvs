### 1.3 三条横切结论

1. **"骨架"高度同质**：`主题/剧本 → LLM 产文案 → 分镜 → 素材（图/视频）→ TTS → 字幕 → ffmpeg` 是共同骨架。本项目在骨架上不占优势，**优势只在骨架上多出来的四样东西**：人审门禁（G0–G5 + 指纹）、人物一致性（定妆 L1/L2）、内容方法论（拍摄稿契约 + 7 个 skill）、逐镜隔离 + 断点续跑。
2. **"工程纪律"两极分化**：头部大项目（Turbo / OpenMontage / VideoLingo / Jellyfish）在 CI、契约、任务中心、成本治理上明显领先；中腰部项目（MoneyPrinterV2 / Toonflow / waoowaoo / openOii）**基本无测试无 CI**。本项目测试量（65 文件 / 1233 例）在主表里排**最前**，但 **CI 是零** —— 这是最刺眼的一条。
3. **分发型项目活得久，自用型项目容易被 star 数掩盖**：ShortGPT（8,003 star）停更一年；Jellyfish 用 OpenAPI 契约 + 任务中心换来 8 个 open issue。**"能不能被别人跑起来"和"能不能被自己维护下去"是两件事**，本项目目前把资源全押在后者（正确），但前者缺一个最小实现（Docker + CI + doctor 报错可读）。

## §4 深度重构方案（按模块）

### 4.0 三条总原则（防过度重构）

1. **已验证的内核不动**：四态退出码、G0–G5 指纹门禁、`stage.py` 表驱动、逐镜隔离 + 熔断、离线 e2e、`--json` 信封 —— 这些是同类里**没有对手**的部分，重构风险最高的地方恰是收益最低的地方。
2. **新能力一律"新增模块 + 明文契约"**：任何新命令/新模块都要配一个判据（`tests/test_architecture.py` 或契约测试），否则不进主干。
3. **每条可独立回滚**：不搞"一次性大重构"。下面每条都标了风档，风档 `L` 的可以连续做，`H` 的必须单独立项并先在 `.scratch/<feature>/` 出 issue。

---

### 4.1 架构分层

| 层 | 现状 | 建议 | 参照 | 风档 |
|---|---|---|---|---|
| Stage（声明层） | `stage.py` 的 `STAGES` + `GATES_BY_STAGE`（表驱动，已有） | **只补文档**，把"Stage = 声明、Driver = 执行"写进一份架构页 | OpenMontage `pipeline_defs/` 与 `skills/pipelines/` 的分离 | **L**（纯文档，0 代码） |
| Gate / Criteria（判定层） | `pipeline.py` 指纹门禁 + `criteria.py` 机器判据 | 把判据表从"三个门"扩到 G5（B3），并允许判据**只报警不放行** | OpenMontage `Quality Gates` + `pre-compose validation` | **L** |
| Provider（能力层） | assets/tts/llm 各自 `if pexels / elif comfyui` | 新增 `lvs/providers/` 适配层 + 只读注册表（B6） | OpenMontage `tool_registry` + 能力信封 | **M** |
| Task（长任务层） | `runlog.jsonl` + stdout | 新增只读任务视图（`lvs tasks`），**不引入 Redis/Celery** | Jellyfish 任务中心（取其"可见性"不取其运维） | **M** |
| Service（服务层） | Flask GUI（自成一体） | GUI 改走同一套 stage/gate 账本（B9 的子集） | Pixelle / Jellyfish | **H** |

**关键判断：不要引入编排框架（LangGraph/Celery/Redis）。** openOii 用 LangGraph 换来的是"恢复执行 + 实时进度"，而本项目**已经有更严的恢复语义**（阶段级 + 逐镜隔离 + 指纹绑定），引入框架只会增加依赖与不确定性。项目自己的反面清单也是这个结论。

### 4.2 目录结构

**现状**：`lvs/` 根平铺 45 个 `.py`，top5 占 31.6% 字节；一个模块（`cast.py` 66 KB）同时承载定妆逻辑、lint 判据、CLI 输出与人审表生成。

**目标（纯搬运 + re-export，不改逻辑）**：

```
lvs/
├── core/         artifact, workspace, config, errors, result, runlog, progress, net, breaker
├── stages/       parse, shots, assets, voice(=tts), build, publish, pipeline, criteria, stage
├── providers/    pexels, comfyui, llm, tts_backends（新层，先薄）
├── tools/        maptool, doctor, summary, cleanup, migrate, board
├── gui/          （不动）
└── cli.py        只做 dispatch + re-export（保证 `lvs.cli:main` 入口不变）
```

- **兼容策略**：`lvs/artifact.py` 等旧路径保留为一行 `from lvs.core.artifact import *` 的 shim（至少保留两个版本周期），`from lvs import cast` 这类既有 import 不破。
- **判据**：新增 `test_architecture.py` 断言 —— `lvs.core.*` 不得 import `lvs.stages.*`；`lvs.stages.*` 不得 import `lvs.cli`（后者已有同类判据）；每个新包必须有 `__init__.py` 且不进 `__all__` 污染。
- **收益**：单文件变小 → `lvs map show` 少读；`lvs map grep --glob "lvs/stages/*.py"` 精确；新人（和 agent）第一次就能猜出文件在哪。
- **风档 M ｜ 维护性 ↑↑ ｜ token ↓（每次定位少读几百行）**

### 4.5 LLM 边界

**现状**（实测）：`llm.py` 只有一个 `LLMClient`（`chat` + `chat_json(retries=1)`）；无缓存、无成本记账；JSON 解析靠 `extract_json` 三路兜底；失败重试是**原样重试**（不把错误反馈给模型）。

**建议（拆三个小模块，都在 `lvs/providers/llm/` 下）**：

| 模块 | 做什么 | 为什么 | 借鉴 |
|---|---|---|---|
| `llm/cache.py` | 内容寻址缓存：`sha256(model + base_url + messages + temperature + **kw)` → 响应；`--no-cache` 逃生阀；命中写 runlog 事件 | 拆镜重跑、调提示词时的重复请求是纯浪费；也让"改了提示词必重算、没改必命中"可验证 | B10 |
| `llm/cost.py` | 从响应 `usage` 记 token 与估算费用，落 `runlog.jsonl`；支持 `cap` 硬拦 | 让"跑一次 shots 多少钱"可见可拦 | B5 |
| `llm/schema.py` | 可选 JSON Schema 强校验（`jsonschema` 走 dev/optional extras）；失败时**把校验错误回灌重试** | 现有 `extract_json` 只保证"是 JSON"，不保证"字段对"；错字段会在下游变成难查的 bug | B2 |

**风档 M ｜ 维护性 ↑↑ ｜ token/费用 ↓↓**

### 4.7 可观测性

分三步，**不追求一次性上结构化日志**：

1. **短期（L）**：把 `runlog` 事件补全 —— 每阶段 `start/end` 带 `duration`、`params_hash`、`cost`、`failures`；`lvs tasks` 只是它的只读视图。
2. **中期（M）**：引入 `logging` 但**不删 print** —— `print` 继续做人类输出，`logging` 走 `--log-json` 走机器输出；这样 400+ 处 print 不必重写（重写 print 是**收益最低、风险最高**的改造，明确不做）。
3. **长期（H）**：进度流（SSE/WebSocket 扇出）让 agent 在长阶段有中间信号；GUI 的 SSE 已有实现，抽出来复用即可。

### 4.8 token 成本（本项目的头号隐性成本）

已有的 S1–S8（`status --brief` / `shots --index|--peek` / docs INDEX / `map` / `doctor --agent` / 测试分层 / 会话纪律）都在生效。**增量建议（全部 L 档）**：

| 编号 | 做什么 | 解决问题 | 验收 |
|---|---|---|---|
| T1 | **产物侧车索引**：写 `shots.json` 时同时写 `shots.index.json`（每镜 id / 人物 / 一句话 / 时长 / 是否图文 beat） | 516 KB 的 `shots.json` 一进上下文就常驻重发；`--index` 现在是**现算**的，仍要解析全量 | 索引文件 ≤ 2% 原体积；新增判据：**任何 > 64 KB 的产物必须配 `*.index.json`** |
| T2 | `lvs resume --json` ≤ 40 行，含"下一道门 + 下一条命令" | 续跑开场要跑 3–4 条命令才拼出全貌 | 输出 ≤ 40 行且含 `next_gate`/`next_command` 字段 |
| T3 | 把"摘要优先"写成判据（T1 的强制化） | 靠纪律会退化，靠测试不会 | `test_architecture.py` 新判据可红 |
| T4 | 文档三层重排（B7）：能力层 / 用法层 / 原理层，INDEX 同步 | `docs/` 顶层 ≈ 20 万 token，"该读哪篇"仍靠判断 | INDEX 每篇标注所属层与"何时读"（已有雏形） |
| T5 | `lvs cost` 把成本显性化 | 现在的省钱靠"感觉" | 跑完 shots 能报出本次 token 与费用 |

**风档 L ｜ 维护性 ↑ ｜ token ↓↓**

### 4.9 GUI 与门禁的"两个世界"（H，需拍板）

`docs/对标-Pixelle-Video.md` 的 grep 结论仍然成立：`grep -rlE "gate|qc|cast" lvs/gui/*.py` **零命中** —— 本项目最强的三件事（门禁 / 巡检 / 定妆）**在 GUI 里点不到**。同类里的 Toonflow（资产画布）、Jellyfish（镜头准备确认工作流）、Pixelle（配置→生成→预览一条龙）都把主流程放在 UI 里。

**最小可行方案**：GUI 不重写，只加三个"只读 + 一个动作"页面 —— 门禁账本视图（读 `gates.json`）、巡检报告视图（读 `qc-*.json`）、定妆审阅表（复用 `lvs cast` 已有产物），动作只有"批准/驳回"。**风险主要在于 Flask 路由与 CLI 账本的双写一致性**，建议先做只读视图。

---

### 4.10 分发形态（H，需拍板）

MoneyPrinterTurbo / Toonflow / FireRed 都证明"能一键跑起来"直接决定 star 与采用。但本项目有两个硬约束：**8 GB 单卡要同时伺候 ComfyUI 与 Qwen3-TTS**（不可共存，已写进纪律），以及 ffmpeg/whisper 的系统依赖。

**建议**：不要做容器化整套（GPU 直通 + 双服务串行会让镜像又大又脆）；优先做**"零模型路径"的 Docker 镜像**（`lvs run --demo` + Pexels + edge-tts 这一条，CPU 可跑），把"能出片"和"能出好片"分开承诺。

### 4.11 明确不做（与项目自己的反面清单一致）

| 不做 | 理由 |
|---|---|
| 引入 LangGraph / Celery / Redis 编排 | 本项目恢复语义更严；引入框架 = 增加不确定性与运维面（openOii 自己定位为学习项目） |
| 把 `stage.py` 表改成 YAML 产线清单 | 表已在 Python 里且被 25 条判据守着；YAML 会引入第二真源（B17 只做**导出**，不做迁移） |
| 重写 400+ 处 `print` 为 logging | 收益最低、风险最高；用双通道增量替代 |
| 多文件配置合并 / 配置继承链 | 单 TOML + env 覆盖已够；复杂度换不来收益 |
| 数字人 / 动作迁移 / 直连云端视频生成 | 那是 Pixelle/waoowaoo 的形态扩展，与"讲书长视频"无关（`docs/对标-Pixelle-Video.md` 结论） |
| 换掉 Flask GUI 做 React 重写 | 与 §4.9 的最小方案直接冲突，收益为负 |

### P0 —— CI 落地（0.5–1 天，B1）★最高 ROI
- **做什么**：新增 `.github/workflows/`（`fast` / `coverage` / `package` 三个 PR 作业 + `slow` 手动作业）。不改任何源码。
- **验证**：① Actions 三作业绿；② 本地 `pytest -m "not slow and not gpu"` 1233 绿；③ `coverage run … && coverage report` 退出码 0；④ `coverage json -o .work/tmp/cov.json` 后 `pytest tests/test_coverage_ratchet.py` **不 skip**（该测试无 json 时自动 skip，是当前"门禁形同虚设"的一处）；⑤ `pip wheel . --no-deps` 后 wheel 含 `lvs/gui/templates/*.html` 与 `static/*`。
- **风险**：仅新增文件，回滚 = 删文件。

### P1 —— 成本 / 缓存 / 续跑三件（2–3 天，B5 + B10 + T1 + T2）
- **做什么**：`llm/cache.py`、`llm/cost.py`、`[budget]` 配置段、`shots.index.json` 侧车索引、`lvs resume` / `lvs cost` 两条命令。
- **验证**：① 不改参数重跑 shots **命中缓存**（LLM 调用数为 0，runlog 可见）；改一个提示词 → 必重算；② 改 TTS `rate` → `voice` 必须重合成（参数指纹生效）；③ `lvs resume --json` ≤ 40 行且含 `next_gate`；④ 新增判据"产物 > 64 KB 必配 index"；⑤ 日常组 1233 绿（碰了 `artifact`/`workspace` → 另跑全量 1294 绿）。
- **风险**：中低；缓存可 `--no-cache` 关闭。

### P2 —— 契约与成片自检（3–5 天，B2 + B3）
- **做什么**：`schemas/`（shots / parse / config / qc 四份首版）、`lvs config check`、`lvs qc --final`（ffprobe + 4 帧抽检 + 音频静音/削波 + 字幕存在）。
- **验证**：① 现有真实产物能通过 schema 校验（拿 `.work/` 里现成任务跑）；② schema 与 `handoff.validate_shots` **互为镜像**（新增判据：人为破坏字段必须两边同时变红）；③ `lvs qc --final` 在 `--demo` 成片上通过、在"抽掉音轨"的坏样本上必须报错；④ G5 自检**默认只报警不改判**（门禁语义不变，`criteria.py` 的"G5 是人的事"原则不破）。
- **风险**：中；ffprobe 部分进 slow 组。

### P3 —— 目录分层 + 供应商注册表（1–2 周，4.2 + B6）
- **做什么**：`core/ stages/ providers/ tools/` 搬运 + shim re-export；`lvs providers` 只读注册表。
- **验证**：① 全量 `pytest` **1294 绿**（这是本阶段唯一合格的验收口径，因为动了公共底座）；② 现有 25 条架构判据 + 新增分层判据全绿；③ `pip wheel . --no-deps` 打包测试绿；④ `lvs map ls` 重新生成；⑤ `lvs pipeline --describe --json` 与 `stage.py` 表逐字段一致。
- **风险**：中高；靠 shim 保证外部 import 不破，可分两次搬（先 `core/`，后 `stages/`）。
