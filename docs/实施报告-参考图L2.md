## 一、补齐 L2：参考图 img2img（原先"半接线"）

### 断点在哪（三处，缺一不可）

L2 是本项目最典型的"**定义了却从不接线**"：

| 断点 | 原先 | 现在 |
|---|---|---|
| ① 上传 | ComfyUI 的 `LoadImage` 只在**它自己的** `input/` 找文件，而定妆照住在 `<素材库>/_cast/…` —— **没有任何代码把图送过去** | 新增 `ComfyClient.upload_image()`（走 `POST /upload/image`，手写 multipart，**不引入 requests 依赖**） |
| ② 参数与占位符 | `generate()` 没有参考图参数；模板里没有 `{{REF_IMAGE}}` | `generate(ref_image=…)` + `REF_IMAGE` / `DENOISE` 两个占位符 |
| ③ 模板 | `workflows/zimage_scene_ref.json` 不存在 | 新建：LoadImage → ImageScale(中心裁切) → VAEEncode → KSampler → VAEDecode → SaveImage |

### 选模板与选图（判据）

拆成两个函数，**先取图、再选模板**：

- `_reference_for(shot, config, lock)` —— 三条全满足才给参考图：
  ① 配了 `[cast].ref_workflow` ② 本镜含人物槽位 ③ 该角色 **`bindable`**
- `_workflow_for(config, ref_available=…)` —— 只有真拿到图才选参考图模板

> **为什么第 ③ 条不能省**：未批准 = "这张脸还没定下来"。拿未批准的候选去锚定，
> 等于把未审核的脸固化成全集标准 —— 比不给更糟，因为它是**一致地错**。
>
> **为什么顺序不能反**：反了会出现"选了参考图模板却没有图可喂"，
> 那时 `generate()` 报的错离根因很远。

### 两条互斥检查（"宁可大声失败"）

- 模板要参考图却没给 → 报错（否则 `LoadImage` 拿到空文件名，ComfyUI 只说"节点参数非法"）
- 给了参考图但模板用不上 → 也报错（那正是"以为开了 L2、其实是纯文生图"）

### 开跑前先汇总（不许让"没生效"看起来像"生效了"）

L2 有**三处会悄悄失效**（模板缺 / 角色未批准 / 本集无槽位），所以 `lvs assets` 现在会先打印：

```
[参考图 L2] 1/3 镜会用**冻结的定妆照**作参考图（img2img 低去噪）
[参考图 L2]   2 镜回退纯文生图：本镜无人物槽位
```

模板缺失属配置错，在这里**当场抛**（不等到第 300 镜）。

### 逐镜记录"用没用参考图"

成功出图后往 `shots.json` 写两个字段（只在**真用了**时写）：

- `reference_image`：这一镜用的参考图路径
- `gen_workflow`：这一镜实际用的工作流模板

理由：翻 300 张图时，"这一镜为什么脸不一样"的答案只有两种 ——
**它没用参考图**，或者**用了但 denoise 没调好**。不记下来就只能猜。

## 二、★ 新查出：人脸巡检（Q006/Q007）**一直是死的**

`lvs qc` 的 Q006「空镜里检出人脸」—— 项目注释里写着这是"**Z-Image 最顽固的失败模式**"。
实测：

| 环节 | 结果 |
|---|---|
| `[qc].face_model` 文件 | ✅ 存在，232,589 字节 |
| `cv2` | ✅ OpenCV 4.10.0 |
| `cv2.FaceDetectorYN.create()` | ❌ **报错**（`Can't read ONNX file`） |
| `onnxruntime` 加载 | ✅ 能加载（结构确是 YuNet：cls/obj/bbox/kps × 3 尺度 = 12 输出） |
| 输出是否可用 | ❌ **退化**：`obj` 恒为 0；`cls` 对**纯黑图与人像几乎同值**（0.775 vs 0.775） |

**结论：这个权重文件不可用** → 两条检查**一次都没真正跑过**，而报告看起来正常。
典型的**静默降级**（本项目最痛恨的一类故障）。

### 改法：把"静默"变成"大声"

- `lvs qc` 现在会打印：
  `[巡检] ⚠ 人脸检测不可用 —— Q006/Q007 本次没有检查` + 原因 + 怎么修
- `lvs doctor` 新增检查项 `人脸检测`，**与 qc 共用同一判据**（`qc.face_model_status`）

> 我**没有**替你换模型：那需要下载并把"换了之后 Q006 判得准不准"在真图上验一遍。
> 本项目纪律：**校验器的价值全在报得准**，不准的校验器比没有更糟。
> 暂时不要这个检查就设 `[qc].enable_faces = false`（这样它不再提示）。

## 三、新增：`doctor` 报"定妆有候选但未批准"

你的定妆库里 5 个角色候选图与审阅表都出好了，但**一个都没 approve**
（`state=IMG`、`refs=[]`）→ `bindable=False`。后果是含 `{NAME}` 的稿会被 G2 拦下，
而用户不知道只差"看一眼审阅表再批"。

现在 `lvs doctor` 会主动报，并直接给出审阅表路径与下一步命令。

## 五、审查（你要求的"再审查一遍"）

### 换了一套判据：专查"我自己的改动"

#### 抓到的第 1 处：**同一件事写了两遍**

我新增的 `qc.face_model_status()` 与既有的 `_load_face_counter()` 各自做了一遍
"找权重 → 建检测器"。**这正是本项目严禁的"同一概念两处定义"** ——
两处判据迟早会漂（一处说能用、另一处说不能用）。

→ 合并成唯一的 `_make_face_detector()`，两个调用方共用结论。
现在全仓只有**一处** `FaceDetectorYN.create`。

#### 抓到的第 2 处：**"定义了却从不读"**

我给 `Resolution.info` 塞了 `ref_note`，但**没有任何代码读它** —— 装饰品。
→ 改成有用的东西：把"用没用参考图"写进 `shots.json`（见 §一末）。

#### 抓到的第 3 处：**有调用点、零测试**

`_report_reference_plan()` 生产里有调用点，但测试数是 0。
→ 补 3 个测试（含"一镜都用不上时必须说明原因"）。

#### 突变测试（守护是不是真的）

本项目纪律：**凡机器可查的守护，必须故意改坏确认它变红。**

我在 `zimage_turbo.json` 里注入假占位符 `{{A_BOGUS_PLACEHOLDER}}`：

```
E  AssertionError: 这些占位符没有值可填，会让 ComfyUI 报「节点参数非法」：
                   ['zimage_turbo.json: A_BOGUS_PLACEHOLDER']
1 failed
```

还原后立刻变绿 → **守护是真的**（不是"看起来在守"）。

#### 测试自己也会写错（两次）

- 断言了 `无人物槽位`，但我传的是 `lock=None`，真实原因是"没有定妆库" → 改断言，并**顺带补了一条专测缺库**的用例
- **预先创建了产物文件**，于是流水线判定"已完成"直接跳过、`resolve_shot` 根本没被调用 —— 测试成了假的。这类"假测试"最危险：它会绿，但它什么都没验。已加注释警示
