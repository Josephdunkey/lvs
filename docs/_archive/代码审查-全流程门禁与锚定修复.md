## 二、门禁设计复核：它真的 fail-closed 吗

这是本轮唯一需要"证明"的设计主张。逐条用测试钉死：

| 场景 | 期望 | 测试 |
|---|---|---|
| 没批准 | 拦 | `test_require_blocks_when_pending` |
| **批准之后产物被改了** | **也要拦** | `test_edit_after_approve_makes_the_gate_stale` |
| 批准之后产物被删了（指纹空） | 拦 | `test_stale_gate_blocks_and_explains` |
| 账本 JSON 坏了 | **退到"全部未批准"**，而不是"全部放行" | `test_corrupt_ledger_fails_closed` |
| 老账本没有指纹字段 | 不算有效批准 | `test_legacy_record_without_fingerprint_is_not_accepted` |
| 产物还没生成 | 拒绝"批准"（空头支票） | `test_approve_refuses_when_no_subject_files` |
| 打回不写原因 | 拒绝 | `test_reject_requires_a_note` |
| 跳过不写原因 | 拒绝 | `test_skip_requires_a_note_and_then_opens` |
| 跳过 | 记录谁/何时/为什么 | `test_skip_is_recorded_with_who_and_why` |

**两条刻意的取舍**（写在代码注释里，不是遗漏）：

1. **指纹用 `size + mtime_ns`，不是内容哈希。**
   G3 的对象是几百张图，逐张读内容要几秒，只 stat 是毫秒级；任何真实写入都会改 `mtime_ns`。
   代价：复制/恢复文件也会判 stale → 多问一句"请重审"。
   这是**安全方向**的误报（多说一句话，不会放过错产物）。
   唯一漏网：把内容改回**完全相同的大小**、同时把 mtime 也改回原值（需要刻意伪造）。

2. **`lvs parse` 不受门禁约束。**
   它免费、可逆，且它的产物正是 G0 的审阅对象 —— 挡住它只会让人无法建立任务，
   却挡不住任何花钱的事。

**默认值是"生效"**：`pipeline.enforce` 缺省 `True`，关掉人审必须是一次显式动作
（`--skip-gates` 或配置），且会打印一行说明。

## 三、发现并修掉的问题

### ★ 3.1 最有价值的一条：**我修 A，引入了 B**

为了修 MIDORI「头发盖住耳朵」，我把最可画的特征前置到锚定最前，结果是：

```
a very short cropped haircut with the ears and the whole nape of the neck fully exposed,
the grown-out ends slightly uneven; a small neat oval face ...; a slight slender build ...,
tomboyish rather than girlish
```

**全句没有一个 girl / woman / person。** 模型于是自己决定画谁 —— 画出了一个**男性**。

这条只有**看图**才能发现（lint 全绿、测试全绿、提示词打印出来也读得通）。
修法是**主语 + `with` + 特征**，让主语和特征落在同一小句里，同时满足
「特征前置」与「必须有主语」两条判据。

> 由此新增规则 `A-nosubject`：整段锚定描述里没有任何人称名词 → 报错。
> 这是把"自己犯过的错"变成判据，而不是只修个案。

### ★ 3.2 定妆照的提示词在自相矛盾

| 冲突 | 现象 | 修法 |
|---|---|---|
| `16:9` vs 1024×1024 方图 | 风格后缀继承自场景图，带着 `16:9`，而 `[cast].width/height` 是方图 | `cast.strip_aspect()` 自动剥掉画幅词（并收拾干净 `grayscale, .` 这种残渣） |
| `dramatic chiaroscuro` vs `even frontal lighting` | 风格后缀要戏剧光，定妆构图要平光 | `config.toml` 加 `[cast].style_suffix`（平光版） |
| 锚定里的衣物清单 vs 「中性胸像」构图 | 突撃隊的锚定列了 5 件衣物 → 出图变成**全身站姿** | 服装移出锚定（见 §3.7，由 `A-diluted` 守住） |

这类"语义打架"正是**同一段锚定出四张不同脸**的机制 —— 模型只能每张各解一次。
第一版里 `16:9`、"dramatic light"、"全身衣物"三个冲突同时存在，那批图只能整批重出。

### 3.3 代词槽位（新功能）里连出四个 bug

| # | 问题 | 怎么发现的 |
|---|---|---|
| 1 | `代词：我（第一人称叙述者）` 里的括号说明让**一个代词都收不进来**（长度超标被过滤） | 单元测试 |
| 2 | 边界判据用 `before in "其无任等乃自"` —— **空串 `in` 任何字符串都为真**，于是**句首的代词全被挡掉**（"她钻出松林"不换） | 单元测试 |
| 3 | 拿**孤立子串**做 lookbehind：`fullmatch("他")` 前面什么都没，判定必然通过 → 「其他人都走了」被换成「其{渡边彻} 人都走了」 | 手工核对 |
| 4 | `渡边` ⊂ `渡边彻`：先换全名得到 `{渡边彻}`，再用简称去搜就命中槽位内部 → 产出 `{{渡边彻}彻}` | 设计复核 |

修法：边界一律**拿原文判**（不是拿截出来的词判）+ **槽位守卫**（交替式正则，让 `{...}` 优先被吃掉）
+ 名字之间**长名优先**。

### ★ 3.4 一个静默产出错图的隐患：比较提及

P2 有一行画面位：`{KIZUKI} ：与渡边彻同龄的十九岁少年…`

「与渡边彻同龄」和「与渡边彻并肩」**句式相同、语义相反** —— 前者只是拿他作参照（他不在场），
后者是他在场。机器分不清，但它把渡边的锚定注进了**木月的镜头** ——
后果是那一镜的脸混进另一个人的特征，不报错、不崩，只是悄悄错。

**处理方式体现本项目的一贯取舍**：不猜。默认按出场处理（多数情况对），
但把这类行**单独列一节**交人复核。机器给判决，人保留推翻权。

### 3.5 别名判据把真别名一起丢了

旧判据是"以「渡边」开头就丢"（为了滤掉"渡边的宿舍室友"这种说明）。
后果：`渡边` 这个**真别名**也被丢掉 —— 而画面位里大量用简称
（P2 的「渡边在她身后半步之外」），丢掉的后果是**那一镜根本不注入锚定**，且不报错。

改成"**含「的」就丢**"：滤掉说明，保留简称。

### ★ 3.6 我删错了一条规则，又把它装回去

先加的 `A-diluted`（服装道具词 ≥ 骨相词 → 报）**在木月上不触发**：
`_FACE_WORDS` 里的 `lean` / `short` 这类通用身体词把计数灌满了。
我当时的判断是"规则不成立，删掉"，换成 `A-expression`（命中木月真正的根因：`a faintly cool smile`）。

**这个判断是错的。** 后来看图发现**突撃隊**的候选全是**全身站姿**，
与「中性胸像」的定妆构图完全不符 —— 根因正是它的锚定里列了 5 件衣物
（衬衫 / 长裤 / 毛衣 / 皮鞋 / 书包）。`A-diluted` 恰好能抓住这一类。

装回去之后在全库复核：**只命中突撃隊一处，其余 7 个锚定零误报。**

> **教训（比规则本身重要）**：一条规则不命中**某一类**案例，不等于规则不成立。
> 我用一个测试用例去否定一条规则 —— 那是**测错了对象**。
> 正确的做法是把规则放到全库上跑，看它命中什么、误报什么。

于是 `A-expression`（表情词 → 五官跟着重采样）与 `A-diluted`（服装道具 → 构图被带跑）
**两条都留着**，各自守一类问题。

### 3.7 突撃隊：服装道具把构图带跑了

改前的锚定：

```
a tall young Japanese man in his early twenties, completely shaved bald head,
prominent angular cheekbones, a plain white shirt, plain black trousers and a
dark blue wool sweater, black leather shoes and a black school bag,
standing very straight with a stiff formal bearing
```

5 件衣物 + "standing very straight" → 模型画的是**全身站姿**。
改成只留骨相：

```
a tall young Japanese man in his early twenties with a completely shaved bald head,
prominent angular cheekbones, a long narrow face, thick straight eyebrows;
a stiff formal bearing
```

服装移回分镜描述（角色该穿什么，本来就该逐镜决定 —— 定妆卡的正文里已经写了三套着装）。

### ★ 3.9 `lvs run` 的检查顺序反了：门禁必须排在 GPU 守卫之前

接了门禁之后暴露出来：`lvs run` 先跑 GPU 前置检查、再跑门禁。于是一个 **G0 都还没审**
的任务，用户会看到：

```
[GPU 守卫] GPU 串行冲突：ComfyUI 正在运行…
  请**关掉 ComfyUI** 后重跑 `lvs voice`。
```

而它真正卡住的原因是**拍摄稿还没审**。让人去关一个跟当前这一步毫无关系的服务，
比不给提示更糟 —— 他会关掉 ComfyUI，重跑，然后再看到门禁提示。

**语义上也不通**：门禁问的是"**该不该**往下走"，守卫问的是"这一步**能不能**跑"。
该不该是更上位的问题。

修法：在 `run_command` 里新增 `_next_stage()`（本次会执行到的第一个阶段），
先对它跑一遍 `_gate_hold`，再进守卫。门禁检查是纯读、无副作用，先跑不浪费任何东西。

新增两个测试钉死顺序：`test_run_reports_gate_before_gpu_guard`（门禁没过 → **一次都不该探测 GPU**）
与 `test_run_reaches_guard_once_gates_are_skipped`（`--skip-gates` 时守卫必须照常生效）。

### 3.10 一处 pre-existing 告警

`lvs/run.py` 里 `f"\n=== parse ===\n已有 parse.json..."` 没有占位符，`pyflakes` 一直报。
顺手修掉（一个字符），保持"新增与改动文件零告警"这条标准。

## 六、已知遗留（未修，记录在案）

1. **顺序陷阱**：`lvs migrate` 是**从原稿重新生成** `_v2/`，对它做过的任何手工改写会被覆盖
   （本轮实际踩到一次，重放了否定式改写才对）。
   理想形态是 `lvs migrate --apply <rules.json>`，把否定式改写规则表吸收进来，
   变成一个命令、一个方向。已写进编排手册 §六.2。
2. **门禁只在 `lvs run` 与命令行生效**：`lvs studio` / `lvs gui` 还没走门禁账本。
3. **G3 巡检的自动判断能力有限**：彩度/完整性可自动判，"空镜长人""单人镜溢出"仍需人眼。
   接入视觉模型做初筛可以，**不能替代人眼**（这是本项目的老教训）。
4. **改名后 `_superseded-旧锚定/` 的目录不会被审阅表收录**（靠 `v\d+` 正则过滤 `_` 前缀），
   这是有意的 —— 但归档目录多了之后需要人工清理。
5. **`lvs gate` 没有"部分批准"**：G3 的对象是几百张图，目前只有"全批/全打回"。
   若出现"只有 3 张要重出"，只能 `--reset` 重审。等真的痛了再做。

## 七、给下一次审查的三条

1. **先看图，再看代码。** 本轮最有价值的发现（§3.1 主语丢失）lint 全绿、测试全绿，
   只有看图才现形。凡是"改了提示词 / 改了锚定"的改动，审查**必须包含看一眼产物**。
2. **规则要在全库上验，不要用单个用例否定它。** §3.6 是本轮最大的方法错误：
   我用"它在木月上不触发"否掉了 `A-diluted`，后来发现它正好抓住突撃隊。
   正确做法：把规则放到**全部**锚定上跑，看命中什么、误报什么 ——
   误报率才是判据，单点命中率不是。
3. **判据必须贴在真实上下文上。** §3.3-3 那个 bug（`fullmatch` 孤立子串）是通用陷阱：
   把片段截出来再判边界，等于没判。
