### Q03 🟠 `shots.json` 有 **6 种**读法，其中 3 种的异常处理是错的（**已实测崩溃**）

**实测现场**（`_probe_qc_loadshots.py`，坏 `shots.json`）：

```
--- 1) Workspace.load_shots(error=MyErr) ---
  ✗ 抛的是 JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 23
    调用方写的是 `except MyErr` —— 接不住，会冒到最外层兜底（内部错误 + 退出码 1）

--- 2) build.run_command（裸 json.loads，绕开 load_shots）---
  ✗ 抛 JSONDecodeError

--- 3) try_load_shots（宽容语义，同一份坏数据）---
   -> {}
```

**三件事同时成立**：

1. `lvs/workspace.py:118` 的 `load_shots` docstring 写"**缺失时**抛 `error`" —— 但它只判了 `is_file()`，
   然后**裸** `json.loads`（:127）。**"存在但坏掉"抛的是 `JSONDecodeError`，不是调用方要的类型**。
   于是 `assets.py:960` / `tts.py:748` / `qc.py:622` 的 `except AssetError/TTSError/QcError` **全部接不住** → 退出码 1（而不是 2）。
2. 退出码 1 按你们自己的定义是"**跑完了**，但有失败件"。可这里根本没跑起来。自动化脚本读退出码会被误导。
3. `build.py:713` 干脆绕开了 `load_shots`，手抄一份裸读 → 同样的崩法，不同的报错路径。

**6 种读法清单**：

| 写法 | 位置 | 坏文件时 |
|---|---|---|
| `ws.load_shots(error=…)` | assets:959, tts:747, qc:622 | 抛 `JSONDecodeError`（❌ 类型不对） |
| `ws.try_load_shots()` | shots:764, studio:292, criteria:57/111, run:362 | `{}`（✅ 宽容） |
| 裸 `json.loads(read_text)` | **build:713**, studio:255, shots:873, publish:508, pipeline:193, run:281 | 崩 |
| `gui/store._load_json()` | store:108 | `default`（✅，但又是另一份实现） |

| `raw` dict 直取 | app.py:327 | 崩 |

**修复（一处修好，6 处受益）**

```python
# lvs/workspace.py
def load_shots(self, *, error: type[Exception] = RuntimeError) -> dict[str, Any]:
    """读取本任务的 `shots.json`；**缺失或坏掉都抛 `error`**（调用方据此给各自的人话）。

    ★ 坏文件必须也抛 `error`：早先这里只判 `is_file()`，坏 JSON 会
    抛 `JSONDecodeError` 冒到最外层 —— 调用方的 `except AssetError` 接不住，
    报"内部错误"、退出码 1（而 1 的语义是"跑完了但有失败件"，是错的）。
    """
    path = self.path("shots.json")
    if not path.is_file():
        raise error(f"未找到 {path}。请先运行：lvs shots --task {self.task}")
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
    except (OSError, ValueError) as exc:      # ValueError 覆盖 JSONDecodeError
        raise error(
            f"{path} 读不动（{exc}）。它可能被写坏或被别的程序占用了；"
            f"确认能修好就修，否则删掉它再跑：lvs shots --task {self.task} --force"
        ) from exc
    if not isinstance(data, dict):
        raise error(f"{path} 顶层不是对象（是 {type(data).__name__}）—— 这不是本工具写出来的文件。")
    return data
```

```python
# lvs/robust.py —— 新增
"""从"外部/历史 JSON"里取值的宽容助手。

为什么要单独一个模块：`int(data.get("x") or 1)` 这种写法在本仓库出现 24 次，
其中 3 次遇到非整数就崩（B03/B04）。这里的每个函数都保证**不抛**，
并且对"值存在但类型不对"给出可用的人话，而不是静默吞掉。
"""
from __future__ import annotations
from typing import Any

def as_int(value: Any, *, default: int) -> int:
    """整数取值：None/""/"0.2"（浮点字符串）/3.0 都能用；实在读不出用 default。"""
    if value is None or value == "":
        return default
    if isinstance(value, bool):          # bool 是 int 的子类，但语义不是整数
        return int(value)
    if isinstance(value, int):
        return value
    if isinstance(value, float):
        return int(value)
    try:
        return int(str(value).strip().split(".")[0])
    except (TypeError, ValueError):
        return default


def as_dict(value: Any) -> dict[str, Any]:
    """必须是对象；不是就当空 dict（调用方按"没有"处理）。"""
    return value if isinstance(value, dict) else {}


def as_list(value: Any) -> list[Any]:
    return value if isinstance(value, list) else []
```

用法对照（B03 那处）：

```python
    force = bool(getattr(args, "force", False))

    only = parse_only(getattr(args, "only", None))

    data, bad = stage.load_stage_shots(ws, error=AssetError)

        return bad
    shots = data["shots"]
    if stage.require_shots_contract(ws, shots, stage="素材（assets）", consumer="assets"):
        return 2

    mode, persisted = _resolve_source_mode(ws, data, args)      # ① 策略
    if mode is None:
        return 2

    targets = _select_shots(shots, only=only, force=force)      # ② 选镜
    with _gpu_guard(config, "assets"):                          # ③ 串行守卫（原先 4 处各抄一遍）

            ws, config, targets, allow_library=allow_library, mode=mode,
```

更刺眼的是**同一个文件里已经有正确写法**（`faces` 同样是 -1 哨兵，但判据做了防护）：

```python
:373   if expect_faces is not None and stats.faces >= 0:      # ✅ 先确认测过
```

**为什么 `stats.ok = False` 兜不住**：`stats.chroma = mean_chroma(img)`（:288）在 `inspect()` 的 try 里，
外层 `except Exception: stats.ok = False`（:296）本来能接住真异常 ——
但 `mean_chroma` **自己把异常吞了**，于是外层看不到任何异常，`ok` 保持 True。
**内部的 try/except 把一次可检测的失败转成了静默通过**。

**修复（最小改动：让 `mean_chroma` 别再自己吞 —— 外层的 `stats.ok = False` 本来就在等着接）**

```python
def mean_chroma(img: Any) -> float:
    """平均彩度：逐像素 `max(R,G,B) - min(R,G,B)` 的均值。

    灰度图必然接近 0；整张偏彩（Z-Image 偶发）会明显抬起来。阈值经验值 5。

    ★ 这里**不吞异常**：测不出来就让它抛 —— `inspect()` 的外层会把 `stats.ok`
    置 False 并计入报告。先前这里 `return -1.0`，而判据是 `chroma > 阈值`，
    于是"测不出来"永远等于"通过"，一张坏图能静默过掉黑白检查。
    """
    small = img.resize((128, 128))
    px = list(small.getdata())
    if not px:                       # 0 像素图：也是"测不出来"
        raise ValueError("图像没有像素（0 像素）")
    total = 0
    ...
```

**守卫**（把哨兵语义钉死）：

```python
def test_chroma_sentinel_never_passes_a_monochrome_check():
```
