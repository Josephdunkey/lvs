## §2 🔴 严重（必须修复）

### E01 🔴 wheel 静默漏打 GUI 的模板与静态资源 —— 装完 `lvs gui` 每个页面都 404

**文件**：`pyproject.toml`（`[tool.setuptools.package-data]`）、`tests/test_packaging.py`

**问题**

`lvs/gui/` 里有 5 个 Jinja 模板和 3 个静态资源，它们是**运行时要读的数据**，不是 `.py`：

```
lvs\gui\templates\base.html  index.html  library.html  settings.html  task.html
lvs\gui\static\app.css  app.js  task.js
```

而 `Flask(__name__, template_folder="templates", static_folder="static")`（`lvs/gui/app.py:127`）
是按 **`lvs/gui/` 这个包目录**去找它们的。可是 `pyproject.toml` 的 package-data 只声明了：

```toml
[tool.setuptools.package-data]
"lvs" = ["../workflows/*.json"]
```

→ **没有一行管 `lvs.gui`**。于是 wheel 里这 8 个资源一个都没有（实测见下）。

**实测：同一份 pyproject，两种构建方式给出两个不同的 wheel**

| 构建方式 | setuptools | wheel 条目 | `lvs/gui/templates/*.html` | `lvs/gui/static/*` |
|---|---|---:|---:|---:|
| `pip wheel .`（**默认隔离**） | 84.0.0（从 PyPI 现取） | 66 | 5 ✅ | 3 ✅ |
| `pip wheel . --no-build-isolation` | 75.1.0（venv 自带） | **58** | **0 ❌** | **0 ❌** |

**根因（三段，缺一段就复现不出来，这也是上一轮没定性的原因）**

1. **venv 里的 setuptools 是 75.1.0**。这个版本**不会**把包目录里的数据文件自动塞进 wheel ——
   它只打 `package-data` 里显式声明的。所以 `lvs/gui/templates/*` 全丢。
2. **隔离构建会去 PyPI 拿 84.0.0**，而新版 setuptools 的行为变了：会**自动**把包内的数据文件带上。
   → "漏声明"这件事在 `pip wheel .`（**不敲参数时的默认命令**）下完全看不出来。
3. **`build/lib/` 是增量目录**。上一次构建留下的 `build/lib/lvs/gui/templates/*.html`
   不会因为"这次没声明"而被删掉，它照样会被打进 wheel。
   → 在同一个仓库里连续构建，坏结果会被上一次的好结果掩盖（我第一轮变异验证就被它骗过一次，见 §8）。

**风险说明**

| 后果 | 说明 |
|---|---|
| `pip install longvideostudio` 之后 GUI 完全不可用 | 首页 404、CSS/JS 404、每个页面 500（模板找不到） |
| **静默** | `pip wheel` / `pip install` 全程**不报任何错**。只有用户点开浏览器才会发现 |
| 现有守卫测试**是绿的** | `test_wheel_contains_the_gui_subpackage` 只断言 `any(n.endswith("app.py") for n in gui)` —— **有 .py 就算过**，模板与静态资源从来不在它的检查范围里。这是"守卫测试本身有盲区"的实测实例 |
| 与仓库既有踩坑同类 | `pyproject.toml` 里那段注释已写过"写死 `packages = ["lvs"]` 会静默漏掉 `lvs.gui`" —— 这次是**同一个坑的第二层**（漏了子包的*数据*），说明只做一次"看起来修好了"不够 |

**修复（已落地）**

`pyproject.toml`：

```toml
[tool.setuptools.package-data]
# 生图工作流模板是**运行时要读的数据**，必须打进包里 —— 光有 .py 不够。
"lvs" = ["../workflows/*.json"]

# ★ GUI 的模板与静态资源同样是**运行时要读的数据**（Flask 按 `lvs/gui/` 找 templates/static）。
#
# 实测（2026-10-05）：只有上面那一行时，`pip wheel .` 产出的 wheel **58 个条目里
# `lvs/gui/templates/*.html`（5 个）与 `lvs/gui/static/*`（3 个）一个都没有** ——
# 装完 `lvs gui` 每个页面都 404，而 pip 全程不报任何错（与"写死 packages 漏掉 lvs.gui" 同一类静默故障）。
# 补上这一行后 wheel 66 个条目，这 8 个资源全在。
"lvs.gui" = ["templates/*.html", "static/*"]
```

**守卫测试（已落地，且已变异验证会变红）**

```python
def test_wheel_contains_gui_templates_and_static(wheel_names: list[str]):
    """★ GUI 的 `templates/` 与 `static/` 必须打进 wheel —— 它们是**运行时要读的数据**。"""
    t_dir = ROOT / "lvs" / "gui" / "templates"
    s_dir = ROOT / "lvs" / "gui" / "static"
    on_disk_t = {p.name for p in t_dir.glob("*.html")}
    on_disk_s = {p.name for p in s_dir.iterdir() if p.is_file()}
    assert on_disk_t and on_disk_s, f"源码树里就找不到 GUI 资源：{t_dir} / {s_dir}"

    packed_t = {Path(n).name for n in wheel_names if "/gui/templates/" in n}
    packed_s = {Path(n).name for n in wheel_names if "/gui/static/" in n}
    missing_t = sorted(on_disk_t - packed_t)
    missing_s = sorted(on_disk_s - packed_s)
    assert missing_t == [], f"GUI 模板没打进 wheel（装完页面 404）：{missing_t}"
    assert missing_s == [], f"GUI 静态资源没打进 wheel（装完样式/脚本 404）：{missing_s}"
```

**★ 光加这条测试还不够 —— 必须同时修掉 `_build_wheel()` 的两个盲区（已落地）**

原来的 `_build_wheel()` 是"在仓库原地 `pip wheel .`"，这**守不住任何东西**（实测：抽掉补丁它照样绿）。
现在改成"**在干净源码副本里、用 `--no-build-isolation` 建**"：

```python
def _build_wheel(tmp_path: Path) -> Path | None:
    """真建一个 wheel —— 在**一份干净的源码副本**里建。

    ## 三件实测出来的事（2026-10-05），缺一件这函数就守不住东西

    1. **必须在干净副本里建**：setuptools 的 `build/lib/` 是**增量**目录 ——
       上一次构建留下的 `build/lib/lvs/gui/templates/*.html` 不会因为
       "这次没声明 package-data"而被删掉，它会**照旧被打进 wheel**。
    2. **必须 `--no-build-isolation`**：隔离构建会去 PyPI 拿最新 setuptools（实测 84.0.0），
       而新版会自动把包目录里的数据文件塞进 wheel —— "漏声明 package-data"这个 bug
       在隔离构建下**看不出来**。换成 venv 自带的 75.1.0 立刻复现。
    3. **只拷运行时需要的东西**：整个仓库含 `.work/`（6.9 GB）与 `.venv/`（2.2 GB），
       复制一遍既慢又没意义。
    """
    src = tmp_path / "src"
    src.mkdir(parents=True, exist_ok=True)
    for name in ("pyproject.toml", "README.md", "LICENSE"):
        f = ROOT / name
        if f.is_file():
            shutil.copy2(f, src / name)
    for name in ("lvs", "workflows"):
        shutil.copytree(ROOT / name, src / name,
                        ignore=shutil.ignore_patterns("__pycache__", "*.pyc"))

    proc = subprocess.run(
        [sys.executable, "-m", "pip", "wheel", ".", "--no-build-isolation",
         "--no-deps", "-w", str(tmp_path), "-q"],
        cwd=src, capture_output=True, text=True, timeout=900,
    )
    if proc.returncode != 0:
        pytest.skip(f"pip wheel 不可用：{proc.stderr[-300:]}")
    wheels = list(tmp_path.glob("*.whl"))
    if not wheels:
        pytest.skip("没有产出 wheel")
    return wheels[0]
```

```python
"""可选依赖清单 —— **唯一真相源**。

为什么要单独一个模块：以前"哪些包可选、缺了会怎样、怎么装"散在三处 ——
`pyproject` 的 extras、各模块的 `try/except`、`doctor` 的提示文案，三处会漂移
（E03 实测：`flask`/`tomlkit`/`Pillow` 连 pyproject 都没进）。
现在：一份表，`doctor` 与报错文案都从这里取。
"""

from __future__ import annotations

from dataclasses import dataclass


@dataclass(frozen=True)
class Optional:
    module: str          # import 名
    package: str         # pip 名（两者常不一样：PIL ↔ Pillow、cv2 ↔ opencv-python）
    extra: str           # `pip install longvideostudio[<extra>]`
    why: str             # 缺了会怎样（写进 doctor 的 hint）


OPTIONALS: tuple[Optional, ...] = (
    Optional("flask", "flask", "gui", "`lvs gui` 启动不了（本地图形界面）"),
    Optional("tomlkit", "tomlkit", "gui", "GUI 的「设置」页改不了 config.toml"),
    Optional("PIL", "Pillow", "image", "`lvs publish` 出不了封面；GUI 缩略图 / 定妆审阅表 / 图文卡也受影响"),
    Optional("numpy", "numpy", "qc", "`lvs qc` 的亮度/清晰度类判据不运行"),
    Optional("cv2", "opencv-python", "qc", "`lvs qc` 的 Q006（空镜长人）/ Q007（人物镜没脸）不运行"),
    Optional("imageio_ffmpeg", "imageio-ffmpeg", "comfy", "系统没装 ffmpeg 时找不到备用的静态 ffmpeg"),
    Optional("requests", "requests", "http", "拆镜（LLM）与 Pexels 取素材不可用"),
    Optional("edge_tts", "edge-tts", "tts", "edge 配音后端不可用"),
    Optional("faster_whisper", "faster-whisper", "align", "本地 TTS 字幕强制对齐不可用（退回估算时长）"),
)


def missing() -> list[Optional]:
    """当前环境缺哪些可选依赖（doctor 与报错文案共用）。"""
    import importlib.util

    return [o for o in OPTIONALS if importlib.util.find_spec(o.module) is None]
```

```python
def run_command(config, ws, args) -> int:  # noqa: ANN001 - 由 cli 传入
    as_json = bool(getattr(args, "json", False))
    by = str(getattr(args, "by", None) or "user")
    note = str(getattr(args, "note", None) or "")

    def _emit(payload: dict, code: int) -> int:
        """★ 写操作也要有回执：`--json` 时一律打 JSON（不是"只读才有"）。

        实测踩过（2026-10-05）：`lvs gate --json --reset` 退出码 0、**stdout 0 字符** ——
        `as_json` 只被 `if not as_json:` 用来**抑制**散文，四条写分支谁都没打 JSON，
        于是"干净 JSON"变成"什么都没有"。agent 的 `json.loads(stdout)` 直接抛异常。
        """
        if as_json:
            print(json.dumps(payload, ensure_ascii=False, indent=2))
        return code

    try:
        if getattr(args, "approve", None):
            st = approve(ws, args.approve, by=by, note=note, config=config)
            if not as_json:
                print(f"✅ {st.gate.id}·{st.gate.title} 已批准（{st.files} 个文件，指纹 {st.fingerprint}）")
                if not st.criterion_ok:
                    print(f"⛔ 但**仍未放行**：自动判据未过 —— {st.criterion_reason}")
                    print("   （判据是放行的必要条件；跑通它之后无需重新批准）")
            return _emit({"task": ws.task, "action": "approve", "gate": st.gate.id,
                          "state": st.state, "criterion_ok": st.criterion_ok,
                          "criterion_reason": st.criterion_reason,
                          "files": st.files, "fingerprint": st.fingerprint}, 0)
        if getattr(args, "reject", None):
            st = reject(ws, args.reject, by=by, note=note, config=config)
            if not as_json:
                print(f"❌ {st.gate.id}·{st.gate.title} 已打回：「{note}」")
            return _emit({"task": ws.task, "action": "reject", "gate": st.gate.id,
                          "state": st.state, "note": note}, 0)
        if getattr(args, "skip", None):
            st = skip(ws, args.skip, by=by, note=note, config=config)
            if not as_json:
                print(f"⏭ {st.gate.id}·{st.gate.title} 已跳过：「{note}」（已记进账本）")
            return _emit({"task": ws.task, "action": "skip", "gate": st.gate.id,
                          "state": st.state, "note": note}, 0)
        if getattr(args, "reset", None) is not None:
            n = reset(ws, args.reset)
            if not as_json:
                print(f"已重置 {n} 道门禁为未批准。改完记得重审。")
            return _emit({"task": ws.task, "action": "reset", "reset": n}, 0)
        ...   # 纯读那条路照旧
    except (GateError, GateBlocked) as exc:
        # ★ 错误也要守契约：`--json` 时错误走 JSON（且**只**走 stdout），散文才走 stdout
        if as_json:
            print(json.dumps({"task": ws.task, "ok": False, "error": str(exc),
                              "exit_code": exc.exit_code}, ensure_ascii=False, indent=2))
        else:
            print(str(exc))
        return exc.exit_code
```

```python
# 第 1 步：新增 lvs/logging_setup.py —— 只管"给人看的散文"这一路
"""把散文输出收拢到一条通道上。

## 为什么不是"全仓改成 logging"

399 处 print 是**给人看的进度与提示**，它们的形态（进度条、emoji、多行缩进）本来就不适合
logging 的格式。真正的痛点是：**没有级别、没有时间戳、没有开关、和 --json 打架**。
所以这里只做三件事：
  ① 给输出一个**级别**（info / warn / error），让 `LVS_LOG_LEVEL=warn` 能把噪声压掉；
  ② 给输出一个**时间戳**（长跑时才知道卡了多久）；
  ③ 统一到 `emit()` 一个出口 —— 以后要改道 stderr、要落文件，只改这一个函数。
"""

from __future__ import annotations

import os
import sys
from datetime import datetime

_LEVELS = {"debug": 10, "info": 20, "warn": 30, "error": 40}
_THRESHOLD = _LEVELS.get(str(os.environ.get("LVS_LOG_LEVEL", "info")).lower(), 20)


def _stamp() -> str:
    return datetime.now().strftime("%H:%M:%S")


def emit(msg: str, level: str = "info", *, stream=None) -> None:
    """统一出口。level 低于阈值就丢弃；`error` 一律走 stderr。"""
    if _LEVELS.get(level, 20) < _THRESHOLD:
        return
    target = stream or (sys.stderr if level in ("warn", "error") else sys.stdout)
    print(f"[{_stamp()}] {msg}", file=target)


def info(msg: str) -> None:
    emit(msg, "info")


def warn(msg: str) -> None:
    emit(msg, "warn")


def error(msg: str) -> None:
    emit(msg, "error")
```

## §7 整体架构改进建议（工程化视角）

### A. 打包：数据文件搬进包里，别再往包外跳

**现状**：`[tool.setuptools.package-data]` 写的是 `"lvs" = ["../workflows/*.json"]` ——
`../` 意味着"包目录的上一级"，也就是**仓库根**。这带来三个后果：
① 干净 clone 若不含 `workflows/`，包就残废（E02）；
② `pip install` 到 `site-packages` 之后，"仓库根"变成了 `site-packages/`，语义飘了；
③ 数据文件在包外，`importlib.resources` 用不了，只能靠 `Path(__file__).parent.parent` 拼路径。

**建议（长期）**：

```
lvs/
  data/
    workflows/sdxl.json  zimage_cast.json  zimage_scene_ref.json  zimage_turbo.json
    templates/…          ← GUI 模板也搬进来
    static/…
```

```python
# lvs/config.py
from importlib.resources import files

def data_dir() -> Path:
    """包内数据根。**不要再写 `Path(__file__).parent.parent`** —— 那会把
    "包的位置"和"仓库的位置"绑死，装到 site-packages 后语义就变了。"""
    return Path(str(files("lvs") / "data"))
```

配套 `pyproject.toml`：

```toml
[tool.setuptools.package-data]
"lvs" = ["data/workflows/*.json", "data/templates/*", "data/static/*"]
```

收益：`workflows/` 与 `lvs/gui/templates` 这类"包外数据"的整类故障（含 E01）**永久消失**。

### B. 依赖：一份表，三处不漂移

`lvs/deps.py` 做唯一真相源（E03 给了完整实现）：
- `pyproject.toml` 的 extras **从它生成**（或至少由 `tests/test_deps.py` 断言两边一致）；
- 所有"探测式 import"的兜底文案从它取；
- `doctor` 的检查项从它生成（少写一个检查函数）。

推荐加一条守卫测试：

```python
def test_pyproject_extras_cover_every_optional_import():

```

### C. 输出：三条通道，各管一件事（现在是"三套设施 + 399 处 print"）

| 通道 | 现状 | 建议 |

### E. 配置：从"能读"到"能校验"

现状很好（§6-14/15），可以再加一层：**未知键告警**。

```python
def check_config_keys(config: Config) -> CheckResult:
    """config.toml 里出现了代码不认识的键 → 大概率是拼错（`[tts] voice` 写成 `voices`）。

    实测背景：`laod`/`vice` 这类拼写错误在 TOML 里**不报错**，
    只会表现成"我明明配了却没生效"（本仓 docs 里已有多起同类排查记录）。
    """
    known = _known_keys()                                   # 从 config.example.toml 或 schema 生成
    unknown = sorted(set(config.keys_flat()) - known)
    if not unknown:
        return CheckResult("配置键", PASS, f"{len(known)} 个键都对得上")
    return CheckResult("配置键", WARN, f"不认识的键：{unknown}",
                       hint="大概率拼错了；对照 config.example.toml")
```

### 8.3 本轮的翻车记录（留给下一位续跑者，省一次 token）

1. **`sys.modules[mod] = None` 模拟缺依赖是错的**。它会把导入系统搞脏，
   报出来的异常是 `import of tomlkit halted; None in sys.modules`，**不是真实机器上的报错**。
   正解：子进程 + `PYTHONPATH` 指向一个只含 `X.py` 的垫片目录，里面 `raise ModuleNotFoundError(...)`。
   ★ 一定要抛 `ModuleNotFoundError`（不是 `ImportError`），否则 `except ModuleNotFoundError`
   的兜底不会触发，你会得到一个**假 bug**（我第一版就误判了 `doctor` 缺 requests 会崩）。
2. **变异验证第一次假绿**。抽掉 `"lvs.gui"` 后测试仍通过 —— 原因是 `build/lib/` 增量，
   上一次构建的模板还在那儿被照旧打包。**结论：变异验证必须在干净副本里做**（已在测试里修掉）。
3. **PowerShell 的 `$` 展开又炸了一次**。`python -c "...'.t4$t'..."` 里 `$t` 被 PS 当成变量，
   后面整条命令都废了。铁律：**复杂引号一律写成 `.py` 文件到 `.work/tmp/` 再跑**。
4. **here-string 被内容里的 `'@` 提前终止**。写大 markdown 时，内容里只要有一行以 `'@` 开头
   （比如示例代码里的 `'@ | Add-Content ...`），`@'...'@` 就断在那里，后面全被当 PowerShell 解析。
   规避：示例里不要出现行首 `'@`。
5. **PS 的 `>` 重定向写出来的是 UTF-16LE**（0xFF BOM）。判"stdout 是不是纯 JSON"必须用
   `subprocess.run(capture_output=True, text=True, encoding="utf-8")`，别用 `>` 重定向再读文件。
