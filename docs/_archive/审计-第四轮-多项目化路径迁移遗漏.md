# 全流程深度审计 · 第四轮 —— 多项目化的路径迁移遗漏

> 前三轮把架构基座打好了（stage / errors / artifact 单一真源 + 24 条架构约束）。
> 这一轮**不再做新架构**，专门找"上一轮 `[paths].lib` 多项目化改造后**漏改的地方**"。
> 因为多项目化恰恰是**最危险的改动**：它把一堆路径从"写死"变成"派生"，
> 任何一处没跟上，都会变成**静默失效**——不报错、不崩，只是读不到东西。

## 审计方法

不靠感觉，靠**交叉比对**：`[paths].lib` 引入后，所有"读定妆库 / 读定妆卡 / 读产物"
的地方，是否都改成了"从 `cast_dir(config)` / `find_card(config)` / `upstream_artifacts` 派生"，
还是还停留在旧的 `cast/lock.json`、`config.get("cast.card")`、`if p.is_file()`。

## 抓到的三个真 bug（都是静默失效）

### ★ Bug 1：`check.py::collect_known_cast` 还读旧路径 `cast/lock.json`

- **现象**：`lvs check` 的 C026（"人物槽位 `{NAME}` 是否在定妆库里"）在真实项目上
  **永远读不到定妆库** → 返回 `None` → 这条检查**静默跳过**。
- **根因**：上一轮把定妆库迁到 `<素材库>/_cast/lock.json`，但 `collect_known_cast`
  只扫 `cast/lock.json`（仓库根），且 `run_command` 调用它时**根本没传 config**。
- **证据**：真机验证 —— `collect_known_cast()`（无 config）返回 `None`；
  而 `cast_dir(config)` 明明指向 `D:\fanshu\...\_cast` 且 `lock.json` 存在、有 9 个人物。
- **修法**：`collect_known_cast(root=None, config=None)`，传 config 时走
  `cast_dir(config)` + `load_lock`；`run_command` 改为 `collect_known_cast(config=config)`。
  没传 config 时保留旧行为（向后兼容 + 既有测试）。

### ★ Bug 2：`migrate.py` 的定妆卡 fallback 用旧字段 `config.get("cast.card")`

- **现象**：定妆库读不到人物时，migrate 退到读定妆卡，但 config 里 `card=""`
  （上一轮已留空、改走自动发现），于是这条退路**也断了**。
- **修法**：`cast_mod.find_card(config) or config.get("cast.card")`。

### ★ Bug 3（最严重）：`artifact.refs()` 只收文件，目录型产物被静默跳过

- **现象**：`voice` 阶段的上游是 `assets` **目录**、`build` 的上游是 `audio` 目录，
  但 `refs()` 写的是 `if p.is_file()`——目录被跳过，于是**血缘根本没记**。
- **后果**：**改了 assets 里的图，`voice` 仍判"已完成"**，拿旧图继续配音合成，
  全程不报错。这正是上一轮 D3 想解决的"拿旧产物往下跑"，但目录型产物漏网了。
- **根因**：`ArtifactRef.of()` 用 `_stat_sig`（单个 stat）。目录的 `mtime` **不会**
  被子文件内容改动触发，所以即使记了目录，单个 stat 也判不出变化。
- **修法**：`ArtifactRef` 增加 `is_dir` 字段；目录用**递归指纹**（`fingerprint()`），
  文件仍用 stat。`unchanged()` 据此分派。`to_dict`/`from_dict` 带 `is_dir`，
  老 manifest 无此字段 → 默认 `False` → 行为不变（向后兼容）。
- **验证**：改 assets 里一张图 → `is_stage_done("voice")` 从 True 变 False，
  `stale_reason` 报"上游产物已变：assets"。

## 顺手补的：`doctor` 漏检 `[paths].lib`

`doctor` 原来查 9 项，但**不查多项目化最关键的 `[paths].lib`**——而"配了但路径不存在"
正是上面 Bug 1/2/3 的温床。新增 `check_paths_lib`：

- 未配置 → WARN（退回仓库根 `cast/`，多本书会串）
- 配了但路径不存在 → WARN（**最危险的静默失效**）
- 配了但缺定妆卡 → WARN（人物锚定的唯一来源）
- 全好 → PASS

## 方法论小结（第四轮最值得记住的一条）

**多项目化（把路径从写死变成派生）之后，必须做一次"路径迁移遗漏"专项审计。**
不是查功能对不对（功能测试会过），而是查**还有谁在读旧路径、旧字段、旧假设**——
这类漏改全是静默失效，测试绿、看图也看不出来，只有"真机跑一遍 + 交叉比对引用点"能抓到。
