## 二、修掉的问题

### ★ P0-1 `bindable` 只看状态、不看文件在不在

```python
# 改前
return self.state in BINDABLE and bool(self.refs)
# 改后
return self.state in BINDABLE and self.refs and any(Path(r).is_file() for r in self.refs)
```

`lock.json` 说 `state=REF` 但参考图被删/路径变了 → 闸门**放行**、生成照跑、
结果用了个不存在的参考。这是最难查的一类故障（状态与产物不一致）。

### ★ P0-2 `parse_card` 的小节边界只认"长得像人名"的标题

定妆卡里 `### 反廉价感（…）` 与 `### 渡边彻（…）` 同为三级标题。
旧实现只在遇到"人名标题"时才断段，于是 `反廉价感` 一节一路穿到
`## 三、人物定妆卡` 下面，把 `> 用法：…把「锚定描述」整段照抄…` 当成锚定描述，
**凭空造出一个叫 `MOTIF` 的人物**混进定妆库。

修法：边界按**标题层级**判（遇到 ≤ 当前层级的标题就停），并排除 `>` 引文行。
真机复验：9 个人物全部正确，`MOTIF` 消失。

### ★ P0-3 `configure_face_model(enabled=False)` 关不掉

`_FACE_COUNTER` 用 `False` 当"还没找过"的哨兵。只把配置读成 False 而不动哨兵，
第一次 `measure()` 又会惰性加载 —— 配置里的 `enable_faces = false` 是**摆设**。

### P1-1 我自己在提示词里写了否定句

```python
# 改前（定妆构图）
"… sharp focus on the face, no dramatic shadow"
```

本项目头号红线是「cfg=1.0 蒸馏模型不吃负向，否定句里的名词会被画出来」。
写工具的人自己也会犯 —— 现在 `lvs check` 会把这种写法当 **error** 报出来。

### P1-2 `gate_message` 用 `<NAME>` 占位符而不是真名

用户需要的是**能直接粘贴的命令**。改成打印真实人物 ID。

### P1-3 `--sheet` 被判成假值

`nargs="?"` + `const=""` 得到的是**空字符串**（falsy），用真值判断会漏进状态分支。
已改为 `is not None`，并加了钉死这个行为的用例。

### P1-4 无分镜时误报"闸门通过"

`shots.json` 不存在 → `gate_missing` 返回空 → 打印"✓ 闸门通过：本集所有人物都已冻结"。
"没缺人"在没分镜时是**废话**，不是通过。现在分三种情况分别说话：
无法判断 / 闸门无事可做（本集没有槽位）/ 真通过。

### P2-1 否定式规则两处各写一套

`lvs check`（报 error）与 `lvs migrate`（列工作清单）各有一套正则，宽窄不一 ——
用户不知道信哪个。已收敛到 `prompting.NEGATION_RULES` 单一真源。

### P2-2 审阅表只显示最新一轮

`latest_only=True` 会把渡边彻的**第 1 段锚定（19 岁）**藏起来 ——
而"两段都在"恰恰是它需要被审的原因。改为一人一版一行。

---

### ★ P0-4 归档动作暴露的 GUI 真 bug：`/media/` 路由绕过 app 的 root

全量回归跑出 **1 个失败**：`test_gui.py::RoutesTest::test_media_serves_inside_task`（404）。

排查后确认：**失败是我的归档动作触发的，但根因是 `lvs/gui/app.py` 的真 bug**。

```python
# 改前：这四个辅助函数吃 store 的默认 root（= PROJECT_ROOT）
def _task_dir_or_404(name):        d = store.task_dir(name)
def _shot_source(task, sid):       data = store.read_shots(task)
def _shot_asset(task, sid):        data = store.read_shots(task) / store.task_dir(task)
```

同一文件里**其余 15 处**都老老实实传了 `app.config["LVS_ROOT"]`，只有这四个漏了。
它们曾经"碰巧正确"——因为测试用临时 root 造任务，而**仓库根的 `.work/demo/` 恰好存在**
（9 月 27 日冒烟跑留下的那个），于是 404 被这份巧合遮住了。我把 `.work/demo/` 归档掉，
巧合没了，bug 就露出来了。

后果有两层：
- 测试里 `create_app(tmp)` 造的任务取不到产物
- 真机上用 `--root` 指向别处时，**产物服务会指向另一个目录树**

已修：新增 `_root()` 走 `current_app.config["LVS_ROOT"]`，四处全部接上。
复验：`test_media_serves_inside_task` / `test_media_blocks_traversal` **2 passed**，
`-k "media or thumb or task_api or shots_api"` **6 passed**。

## 五、与项目既有纪律的一致性

本次改动遵守了已有约定，未引入新范式：

- ✅ **文件即状态**：定妆库、巡检报告、迁移报告全部落盘可读可手改
- ✅ **换模型 = 换模板**：定妆照走 `workflows/zimage_cast.json`，代码不含模型知识
- ✅ **失败隔离**：`lvs cast --render A,B` 单个失败不影响其余
- ✅ **不静默失败**：闸门拦住时打印**怎么修**；自动转灰度会记账；库未命中会报出来
- ✅ **绝不改用户原文件**：迁移只写 `_v2/`；素材库命中是复制
- ⚠️ 一处**有意违反**：闸门用 `return 2` 拒绝执行（而不是打印警告后继续）。
  理由是这类错误会让**整集**产物作废，代价远大于"打断一次自动流程"。
