## 四、v2 迁移做了什么

```powershell
lvs migrate "05-拍摄稿/001-…-拍摄稿.md"      # 原稿一字不动，产物落 05-拍摄稿/_v2/
```

- **机械部分（自动）**：每条 `[画面位]` 补 `[场景]` / `[图表]` 标注（判据与生图分流同一套）；
  提到人物名的换 `{NAME}` 槽位
- **判断部分（列清单交人）**：否定式不改 —— 「旗面空白」该改成「平整的单色棉布」还是
  「被风抻平」，机器猜不出来。清单见 `<稿名>-迁移报告.md` 的「⚠ 待人工判断」
- **改写记账**：31 处改写逐条落盘在 `_v2/_否定式改写记录.md`（原串 → 新串 → 为什么）

### 迁移的已知局限（诚实记录）

- **代词解不了**：`直子的左手握住他的手` → 只换了 `{NAOKO}`，「他」（渡边）留成中文。
  自动迁移能处理具名引用，处理不了代词。需要人工补。
- **槽位偏少是正常的**：第一章 40 条画面位只补了 5 处，因为其余画面位是空镜/物件/
  群体镜，本来就没有具名人物。**少不等于漏**。

## 五、流程编排改动一览

```
parse ──► shots ──► ★cast ──► assets ──► voice ──► build
  │        │          │         │          │        │
 G0门     G1门       G2门      G3门       G4门     G5门
格式校验  提示词体检  定妆审批   生图巡检   音画对齐  成片验收
```

| 新增命令 | 闸门 | 行为 |
|---|---|---|
| `lvs check` | G0 | 报 error / warn / info，带行号与改法 |
| `lvs migrate` | — | 补标注与槽位；否定式列清单 |
| `lvs cast` | G2 | 提取 → 出候选 → 审阅表 → `approve` / `reject` → `lock.json` 三态 |
| `lvs qc` | G3 | 分块查完整性 / 彩度（可自动转灰度）/ 人数 / 提示词版本 |

**闸门是报错不是警告**：`lvs assets` 在人物未冻结时会**拒绝执行**并打印怎么修
（`--no-cast-gate` 才跳过）。理由就是那 479 张图。

## 七、本次修掉的 5 个真 bug（都是测试/真机逼出来的）

| # | 问题 | 后果 |
|---|---|---|
| 1 | `bindable` 只看 state、不看参考图文件在不在 | state=REF 但图被删 → 闸门**静默放行**，用了不存在的参考 |
| 2 | `gate_message` 里写 `<NAME>` 占位符 | 用户拿不到能直接粘贴的命令 |
| 3 | `cast_prompt` 的定妆构图里写了 `no dramatic shadow` | **我自己在提示词里写否定句** —— 正是本项目的头号红线 |
| 4 | `parse_card` 的小节边界只认"像人名"的标题 | `### 反廉价感` 穿到 `## 三` 下面，把引文当锚定描述，**凭空造出一个人物 `MOTIF`** |
| 5 | `check` 与 `migrate` 各写一套否定式规则 | 两个工具报的不一样，用户不知道信哪个 → 收敛到 `prompting.NEGATION_RULES` |

第 3 条尤其值得记：**"不要写否定句"这条规则，写了工具的人自己也会犯。**
所以它现在不只写在文档里 —— `lvs check` 会把它当 error 报出来。
