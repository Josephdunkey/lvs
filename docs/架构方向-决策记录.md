# 架构方向 · 决策记录（2026-10-03）

> 起因：讨论「项目架构与 agent 编排的优点与不足」。
> 结论先行：**骨架是对的**，缺口集中在「可观测性 / 门禁与巡检接线 / 给 agent 的运行时契约」。
> 硬约束：**目标机器 RTX 4060 Laptop · 8GB 显存 / 16GB 内存**（实测显存 8188 MiB，内存可用常仅 ~4GB）。
> 全程贯穿一条验收纪律：**不许把现有优点改没了**（见 §5）。

---

## 一、现状：优点（都被代码核实过）

| # | 优点 | 证据 |
|---|---|---|
| 1 | **LLM 只出现在不可替代的一处** | 全库扫描：`llm` 只被 `shots.py` 引用（拆镜）。合成分镜用 ffmpeg、逐镜对位用代码 |
| 2 | **人审门禁 + 指纹绑定** | 六道门 G0–G5 fail-closed；批准记产物指纹，产物被改 → 批准自动失效 |
| 3 | **文件即状态 + 产物血缘** | `manifest.json` + `artifact.refs()`（含**目录级递归指纹**）；不需数据库，天然跨进程 |
| 4 | **失败语义分层** | `0` 成功 / `1` 有失败件 / `2` 输入不对 / `3` 等人审 —— 可被程序判断 |
| 5 | **单一真源 + 架构判据** | `stage` / `errors` / `artifact` / `styles` / `handoff` / `breaker` 各有唯一 owner；29 条架构测试守着 |
| 6 | **已经为 agent 留了接口** | `gate --json`（含 `next.stage_hint`）、`styles --json`、`gate --by`（帮助写明"Agent 代批时写 agent"） |

## 二、现状：不足（按严重度）

| # | 不足 | 证据 |
|---|---|---|
| 1 | ★★ **门禁与巡检没接线** | G3 的 `what` 写「全部图 **+ 巡检结论**」、`why` 写「每块 24 张过眼」，但 `pipeline.subjects()` 对 G3 **只返回 `assets` 目录**，`pipeline.py` 里 `qc` 出现 0 次 → **可以跳过 `lvs qc` 直接批准 G3** |
| 2 | ★★ **工作命令无机器可读结果** | `lvs assets` 只打印中文散文「素材获取完成：新取 X，跳过 Y，失败 Z」。agent 要拿"几镜失败"只能正则中文 —— 措辞一改脚本就断（本项目老坑型） |
| 3 | ★ **无统一的阶段状态出口** | `gate --json` 只覆盖门禁；"哪些阶段做完了"得直接读 `manifest.json` → 把 agent 绑死在内部结构上 |
| 4 | ★ **可观测性≈0** | 无 logging 模块；`StageResult.seconds` **算出来但只打 stdout、不落盘**；无成本/token 统计。跑 8 小时挂了只剩滚掉的 stdout |
| 5 | ★ **manifest 写回非原子 + 每镜写一次** | `_write_manifest()` 整文件 `write_text`（先截断再写），无锁无临时文件；`_progress()` **每镜调一次** → 654 镜 = 654 次整文件重写。写坏后 `_read_manifest` 会**静默重建成空** → **断点续跑全部丢失** |
| 6 | **端到端无自动验证** | 769 测试多为单元级；`--demo` **刻意跳过 `assets`**，且 `voice` 仍走真实 TTS（只有 `edge`=联网 / `openai_speech`=吃显存两个后端，**无离线桩**） |
| 7 | **门禁不分级** | 六道门一样重，G3 是 654 张图 —— 人看不完，实际会退化成"扫一眼就批" |

## 三、关键判定：生图并行在这台机器上是**非选项**

| 事实 | 数值 |
|---|---|
| 显存总量 | 8188 MiB |
| ComfyUI 加载模型后常驻 | ~6 GB |
| 生成时可用余量 | ~2.6 GB（`guard.py` 已论证这是**正常可用**状态） |
| 两个并发生图需要 | ~12 GB+ → **不可能** |

→ 「654 镜 × ~20s = 数小时」这个瓶颈**无解于并行**。真正的杠杆是**别白跑**：
幂等（已有）、**早发现废批**（qc 已有、但没接进门禁 → 见 §4 的 ③）、减镜数。

> `voice` 用 edge-tts 是联网合成、不占显存，理论上可并发；但收益远小于生图，暂不做。
> 唯一还有余量的是**网络等待**（Pexels 下载 / 素材库扫描），可重叠，收益有限。

## 四、已定的五条分支

| # | 决策 | 关键约束 |
|---|---|---|
| **定位** | **走向 agent 编排** | — |
| **落点** | **A 为主**：`lvs` 保持确定性，agent 在**外部**驱动（读 `--json` → 敲命令 → 看门禁） | 明确**不做** C（让 LLM 决定下一阶段）——那会让门禁的 fail-closed 失效 |
| **①** | **结果契约**：工作命令（`parse`/`shots`/`assets`/`voice`/`build`/`qc`）加 `--json`，**共用统一信封** | **只锁 5 个决策字段**：`ok` / `status` / `exit_code` / `counts.failed` / `next_hint`（测试守住）；其余字段自由扩展 |
| **②** | **只修 manifest 原子写 + 写回节流**；并行**暂缓** | `exit_code` **复用 CLI 同一个值**，不另立一套状态码（避免"两处定义同一件事"） |
| **③** | **门禁补自动判据**（纯接线） | G1 过 `handoff` 契约 / G3 要 qc 报告存在**且无 error** / G4 音轨齐+字幕在。`放行 = 人批准 AND 自动判据通过` → **严格加强**。(b) 人工分级归外部 agent，暂不做 |
| **④** | **可观测性最小可用版** | 阶段耗时落 manifest；`logs/run-*.jsonl` 记逐镜事件。**不上框架、不起服务** |
| **⑤** | **建完整离线端到端** | 补 `tts.backend="silent"`（ffmpeg 按字数估时长生成静音轨）+ 让 `assets` 能离线跑（复用 `_demo_images` 的占位图能力）；跑通 `parse→shots→assets→voice→build` 全链离线 |

## 五、验收纪律：不许把优点改没了

每项改动都必须声明"它保住了哪条优点"，并写成**可检查的**验收项：

| 改动 | 必须保住的优点 | 怎么验 |
|---|---|---|
| ① 结果契约 | 退出码四态、单一真源 | `exit_code` 字段必须**等于** CLI 退出码（测试断言两者一致） |
| ② manifest 原子写 | 断点续跑、可人工读 | 写坏/中断后 `stages` 不丢；文件仍是可读 JSON（缩进不变） |
| ③ 门禁自动判据 | **fail-closed**（只能更严） | 断言：自动判据不通过时，即使人已批准**也不放行** |
| ④ 可观测性 | 不上新依赖、不改变行为 | 新增文件只增不改；关掉它流水线行为不变 |
| ⑤ 离线 E2E | 不削弱真实路径 | 离线路径走**同一套** `stage.py` 与 `run_command`，不另写一套 |

**共同红线**：不改阶段顺序、不改门禁语义的"未批准不放行"、不把 LLM 引入确定性环节、不引入外部服务/框架依赖。

## 六、建议排期（有依赖）

```
阶段 1  ② manifest 原子写 + 节流    零风险、自包含、直接可测，且修掉今天就在的隐藏 bug
阶段 2  ⑤ 离线端到端                 安全网 —— 后面每项改动都靠它证明"整条链没断"
阶段 3  ① 结果契约                   agent 地基，纯增量
阶段 4  ③a 门禁自动判据              改动门禁语义，必须先有安全网
阶段 5  ④ 可观测性                   最后做，也让前四项都受益
```

依赖关系：**⑤ 必须在 ③a 之前**（③a 动门禁语义，没有安全网就是盲改）；
**① 必须在 ③a 的 agent 初审之前**（agent 需要稳定的输入契约）。

## 七、本次**没有**决定的

- 并行（等真机测出 `--concurrency` 的安全值；当前判定：生图并行非选项）
- 人工分级看图（(b)）、VLM 语义初审 → 归 A 的外部 agent
- 成本/token 统计（本流水线 LLM 只用一次，优先级低于可观测性）
- `run_command` 拆成"核心函数 + CLI 适配器"（可维护性问题，非缺陷）
