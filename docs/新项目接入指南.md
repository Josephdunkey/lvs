# 新项目接入指南

> `lvs` 服务的**不止一本书**。这份指南说的是：拿到一本新书（或一个新题材）时，
> 怎么把它接进流水线 —— 目标是**一条命令 + 三件事**，而不是对着一堆路径猜。

---

## 三十秒版

```bash
# 1) 建骨架 + 生成项目配置（一条命令）
lvs init "D:/fanshu/<书名>/10-语料/知识视频素材库" --name <项目名>

# 2) 选画面风格
lvs styles --config config.<项目名>.toml          # 看全部 30 个预设

# 3) 之后所有命令都带上这份项目配置
lvs gate --task <任务> --config config.<项目名>.toml
```

`lvs init` 会做四件事，并告诉你**还差什么**：

```
接入项目：某书
  素材库：D:/fanshu/某书/10-语料/知识视频素材库
  ✓ 新建 00-设定  01-素材卡  04-图片素材  05-拍摄稿  06-分镜提示词  07-成片  _cast
  ✓ 风格骨架 …/00-设定/风格预设.toml
  ✓ 项目配置 D:/LongVideoStudio/config.某书.toml
还差 2 步：
  · 还没有定妆卡 —— 这是人物一致性的唯一来源，必须人写
  · 还没有拍摄稿 —— 用 newmuyu 拆书技能产出到 05-拍摄稿/
```

---

## 一、什么跟着"书"走，什么是共用的

这是接入新项目时唯一需要想清楚的事。

| 跟着书走（放项目 config / 素材库） | 全机共用（放主 `config.toml`） |
|---|---|
| **画面风格**（这本书长什么样） | ComfyUI 地址 / 模型 / 工作流模板 |
| **定妆库**（跨集共享的那批脸） | TTS 服务地址与后端 |
| **定妆卡**（人写的锚定描述） | Pexels API key |
| **任务名**（`NW01P1` / `K005`…） | 通用素材库目录（`[library].dirs`） |
| 拍摄稿、成片、图片素材 | 人脸权重 `yunet.onnx` |

**判据**：换一本书时，这一项**必须**变吗？必须变 → 项目级；不变 → 装机级。

> ⚠ 最常见的接错法：把风格写进主 `config.toml`。换第二本书时忘了改，
> 于是"这本书的图和上一本一个调"—— 而这**不会报错**。

## 二、素材库目录契约

`lvs init` 建的骨架，编号沿用拆书技能（newmuyu）的约定，**不要改号**：

| 目录 | 放什么 | 谁产出 |
|---|---|---|
| `00-设定/` | 定妆卡、风格预设、音色设定 | **人写** |
| `01-素材卡/` | 每期的讲稿与内容素材包 | newmuyu 拆书技能 |
| `04-图片素材/` | 分镜图 | `lvs assets` |
| `05-拍摄稿/` | 拍摄稿；迁移产物落 `_v2/` | newmuyu + `lvs migrate` |
| `06-分镜提示词/` | 分镜总表、提示词清单 | newmuyu |
| `07-成片/` | 交付成片 | `lvs build` |
| `_cast/` | 定妆库（跨集共享） | `lvs cast` |

**只有 `00-设定/` 与 `05-拍摄稿/` 是人写的**，其余都是产物 —— 删了能重跑出来。

### 3.2 加自己的风格（**不改代码**）

风格有四个来源，按**具体程度**排序：

| 优先级 | 来源 | 写在哪儿 | 用途 |
|---|---|---|---|
| 1 | `--style-file` | 命令行 | 临时试 |
| 2 | 项目风格文件 | `<素材库>/00-设定/风格预设.toml` | ★ **某一本书专属** |
| 3 | `[styles.<名>]` | 装机 `config.toml` | 本机常做的题材 |
| 4 | 内置 30 个 | 代码 | 开箱兜底 |

```toml
# <素材库>/00-设定/风格预设.toml
default = "my-book-style"

[styles.my-book-style]
desc = "这本书的调子"
tags = ["项目自定义"]
monochrome = false        # ★ 决定 lvs qc 要不要查彩度
suffix = "cinematic still, warm dust haze, shallow depth of field, single full-frame composition, 16:9 composition"
```

### 3.3 写 suffix 的三条红线

**这三条都是实机踩出来的**，`tests/test_styles.py` 会对全部内置预设自动检查：

1. **不写艺术家姓名。** cfg=1.0 的蒸馏模型不区分"风格"与"主体" ——
   `in the style of X` 会被字面画成「X 本人」。
2. **不写否定词。** 这类模型没有负向引导，否定句里的名词会被**原样画出来**。
   `no shading` → 出现 shading；`no text` → 出现乱码文字。
   零文字要靠**正面**陈述：`blank unmarked surfaces`。
   这条比拍摄稿的 `C021` **更严**（C021 的名词表只覆盖 people/text/face 那一类，
   管不到 shading / gradients / anti-aliasing）。实测踩过：
   `minimal-line-art` 写了 `no shading and no fill`。
3. **不写多格词。** `dynamic panel composition` 会被读成「漫画分格纸」，
   模型往格子里填人（实测 1 人 → 2 人）。要单幅就明写
   `single full-frame composition, one uninterrupted picture`。

### 3.4 `monochrome` 为什么重要

"本产线要求纯黑白"曾经是**流水线常数**（写在 `[qc].chroma_max` 里）。
换成油画 / 水彩 / 赛博题材后，彩度超标是**对的** ——
所以"是否单色"跟着风格走：`lvs qc` 只对 `monochrome = true` 的风格查彩度，
其余会直接打印「风格不要求单色 → 跳过彩度检查」。

**判据要跟着画面走，不是跟着"看着像黑白"走**：`old-photo-sepia`（棕褐老照片）
标的是 `monochrome = false` —— 棕调是有色度的，标成单色会让 qc 把正常棕调报成异常。

## 四、定妆卡

人物一致性的**唯一来源**。`lvs init` 不会替你写（那是创作，不是脚手架）。

位置：`<素材库>/00-设定/*定妆卡*.md`（只有一份时自动认；多份会提示你指定）。

写法约定见 `docs/拍摄稿格式契约.md` §4.4；判据是 `lvs cast --lint` 的**九条**
（顺序 / 主语 / 动作 / 度量 / 表情 / 服装道具 / 比喻 / 长度 / 否定式），中英双语都认。

> ⚠ **`--lint` 全绿 ≠ 图对。** 它只筛写法；验收永远是**看图**。
> 本项目最贵的一个错误（锚定丢了主语、角色被画错性别）lint 当时全绿。

## 五、门禁跟着任务走，不跟着项目走

六道门（G0–G5）的账本落在 `.work/<任务>/gates.json` —— **任务级**。
所以同一个项目里每一集有自己的一套门禁，互不干扰。

```bash
lvs gate --task <任务> --config config.<项目>.toml                  # 看
lvs gate --task <任务> --approve G0 --note "稿子OK" --config …
```

## 六、把一个已有项目接过来

如果这棵素材库是手工建的（比如《挪威的森林》），不需要重建：

```bash
lvs init "D:/fanshu/挪威的森林/10-语料/知识视频素材库" --name norway
#   · 已存在的目录不会被动（会打印 `已存在 N 个目录（未改动）`）
#   · 已有的 config 不会被覆盖
```

然后在主 `config.toml` 里把显式路径换成一行：

```toml
[paths]
lib = "D:/fanshu/挪威的森林/10-语料/知识视频素材库"

[cast]
dir = ""      # 自动 → <lib>/_cast
card = ""     # 自动 → <lib>/00-设定/*定妆卡*.md
```

> 这个替换是**等价**的（`D:\LongVideoStudio\config.toml` 已经这么改并验证过），
> 但它把"5 个手填路径"变成"1 个"，而且定妆卡多份时会提示你，不再静默挑一份。

## 七、常见错误

| 症状 | 原因 | 怎么修 |
|---|---|---|
| 出图和上一本书一个调 | 风格写在主 config 里，换书忘了改 | 把风格写进该书的 `00-设定/风格预设.toml` |
| 定妆库"凭空多出一个空目录" | `lvs init` 建 `_cast`，而 config 里手填了 `cast` | 清空 `[cast].dir` 让它从 `[paths].lib` 派生 |
| 彩度告警刷屏但图是对的 | 用了彩色风格，但 `monochrome` 没标或标错了 | 在风格文件里写 `monochrome = false`（棕调老照片同理） |
| `lvs qc` 说"风格不要求单色" | 同上（这是**提示**不是错误） | 这是正常行为；确实要强制查彩度就把风格改成单色 |
| 报「未知画面风格」 | 名字打错 / 项目风格文件没被读到 | `lvs styles --json` 看实际读到了哪些、来源是什么 |
| 骨架目录编号被改了 | 拆书技能的产物目录与流水线读的不是同一棵树 | 别改号；`00/01/04/05/06/07` 是契约 |

---

## 八、一句话总结

> **一本书 = 一个素材库 + 一份项目 config。**
> `lvs init` 建它，`lvs styles` 选风格，`lvs gate` 走门禁；
> 其余的东西（模型、音色、密钥）全机共用，不跟着书跑。
