> 日期：2026-10-02 ｜ 起因：挪威线两天的试做不满意；用户要求重审「拆镜 → 提示词 → 生图」的编排，
> 并在出图前加定妆照审批、出图过程中加异常巡检。
> 参考项目：ArcReel（角色设计图优先 + 人机确认 + 断点续传）、Drama Skills（11 步 skill / 五份 Markdown 事实 /
> REF-* 三态）、Toonflow（三层 Agent + 角色锚定）、SHOTWISE（资产库 + 中断恢复）、
> Pixo（Project/Episode 资产库共享 + Agent 自动 Review）、Runway Agent（大纲先审后生成）。
> 产出目标：**一本书 → N 集成片，全自动跑，每个环节有审阅门禁，人与机器各管一段。**

## 一、现状诊断（为什么挪威线不满意）

### 1.1 现有链路

```
parse（解析拍摄稿） → shots（LLM 拆镜+提示词） → assets（翻库 / Pexels / ComfyUI 生图） → voice（配音+字幕） → build（ffmpeg 合成）
      .work/<task>/        shots.json              assets/local/*.png            audio/            final.mp4
```

生图这一支的真实形态（`lvs/assets.py → _gen_local`）：

```python
generate(shot["prompt"], dst, workflow="zimage_turbo.json", seed=base+shot_id)
```

**一句话：逐镜独立文生图，镜与镜之间没有任何共享的视觉锚。**

### 1.2 五个结构性问题

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| **P1** | **人物一致性只靠文字** | 定妆卡是 md 里的英文锚定描述，每镜靠人肉逐字复用；无参考图、无 LoRA、无 IP-Adapter | 直子被画成男人；跨镜脸在漂 |
| **P2** | **没有审阅门** | `shots → assets` 一路跑到底；没有"停下来给你看"的阶段 | 全片错误在成片后才发现 |
| **P3** | **生图无内置巡检** | 温控/续跑/彩度修正都在**素材库外部脚本**（`chain_gen.py` / `run_with_heal.py` / `check_images.py`），不在 `lvs` 里 | 换一本书就要重写一遍；中断即失控 |
| **P4** | **提示词体检靠外部脚本** | `verify_prompts.py` 在素材库 `99-工具/`，检查的是"真正送进模型的文本" | 体检与生成脱节，改完还要手工同步两处 |
| **P5** | **缓存只防"静默复用"，不防"错图"** | `_request_key` 指纹已实现（做了对的事） | 但错误内容仍需人工发现 |

### 1.3 已做对、要保住的东西

- **文件即状态**：`.work/<task>/manifest.json` + 阶段化 + 幂等 + 失败隔离（D10）—— 比内存状态好，别改
- **请求指纹**：`assets/_src/shot-NNN.key`（票据 46）—— 防镜表重排后静默复用错图
- **失败隔离**：单镜失败只标该镜，其余继续（票据 09）
- **模板即模型**：换模型 = 换 `workflows/*.json`，代码零改动（D11）
- **显存守卫**：生图与本地 TTS 不同时驻留（D6）
- **风格预设不可静默回退**：未知风格名报错而非退回默认
- **GPU 温控 + 断点续跑**：已在外部脚本验证有效，逻辑要内化

│   G0门     G1门       G2门      G3门       G4门     G5门     │

| 门禁 | 位置 | 检查什么 | 不过怎么办 |
|---|---|---|---|
| **G0** | parse 前 | 拍摄稿格式契约（`lvs check`） | 列出所有降级点，拒绝进 parse |
| **G1** | shots 后 | 提示词机器体检（否定句/道具淋洒/中文术语/占位符残留/人物缺性别词）+ 分镜表人审 | 全绿才放行；人审可改 `shots.json` 后重跑 |

| **G4** | voice 后 | 音画同步（`Σ镜音频 + (镜数-1)×gap == video-track` 偏差 <0.5s） | 报错，不静默 |

## 三、G2 定妆门禁（本方案核心）

### 3.1 为什么必须先做这个

调研的三个项目给出同一个答案：

- **ArcReel**：「generate locked character reference images first, before any scene work begins.
  The pipeline **won't move to storyboards until the character and clue assets exist**.
  这不是新想法——影视制作一直是先定妆再生产——但它是**第一个把这件事做成结构性约束而非建议**的开源流水线。」
- **Drama Skills**：用 **REF-* 三态** 表达同一件事——只有「已存在且已核验」的图才能绑进生成槽位。
- **Toonflow**：角色锚定系统，跨场景保持人物外貌/服装/道具。
- **试片实测（我们的血泪）**：4 张小样本看不出问题，**必须在真实镜上试片读图**；空镜会长人、手部会长脸、人物性别会混。

结论：**人物一致性不能靠提示词祈祷，要靠"先冻结参考，再引用"的架构约束。**

### 3.2 新增阶段 `lvs cast`

```
lvs cast --task NW01              # 提取人物 → 出定妆照 → 出对比表 → 等人审
lvs cast --task NW01 --approve NAOKO,REIKO    # 逐个批准
lvs cast --task NW01 --reject NAOKO=3 --note "脸太圆"   # 打回第3版
```

**产物**：

```
.work/<task>/cast/
├── cast.json                # 人物登记表：ID / 名称 / 原著依据 / 锚定描述 / 出现镜号
├── lock.json                # ★ 冻结参考（只有 approved 的才写进来）
├── NAOKO/
│   ├── ref-01-neutral.png   # 中性胸像（基准脸）
│   ├── ref-02-three-quarter.png
│   ├── ref-03-outdoor.png
│   ├── v1/ v2/ v3/          # 每轮候选
│   └── _rejected/           # 被打回的，带 note
├── MIDORI/ …
└── _contact-sheet.png       # 五景验收表（见 §3.4）
```

### 3.3 `lock.json` 的结构（照搬 REF-* 三态思想）

```json
{
  "version": 1,
  "approved_at": "2026-10-03T10:12:00+08:00",
  "characters": {
    "NAOKO": {
      "display": "直子",
      "state": "REF",                       // IMG | PLAN | REF  ← 三态
      "anchor": "clearly female, a beautiful slender Japanese young woman around 20, long straight glossy jet-black hair falling smoothly past her shoulders, round soft earlobes with a small dark mole just below the lobe, pale quiet face, large dark deep eyes, slightly downturned gaze",
      "refs": ["cast/NAOKO/ref-01-neutral.png", "cast/NAOKO/ref-02-three-quarter.png"],
      "primary": "cast/NAOKO/ref-01-neutral.png",
      "negative_notes": ["不画成病态惨白", "不画夸张笑容"],
      "source": "原著 第1章[013][016][034]",
      "approved_by": "user"
    }
  },
  "locations": {
    "AMEIRYO": { "state": "REF", "anchor": "a quiet rural sanatorium in a Japanese mountain valley, low wooden buildings, pine forest, snow in winter", "refs": ["cast/AMEIRYO/ref-01.png"] }
  },
  "props": {
    "WELL_MOTIF": { "state": "PLAN", "anchor": "草地上一个看不清的暗井口（被草遮住）", "refs": [] }
  }
}
```

**三态的语义（直接对应 Drama Skills 的 IMG-*/PLAN-*/REF-*）**：

| state | 含义 | 能否绑进生成 |
|---|---|---|
| `IMG` | 只有提示词，还没有图 | ❌ |
| `PLAN` | 你答应要提供参考图，但还没给 | ❌ |
| `REF` | 图已存在、且**已核验** | ✅ **只有它能** |

### 3.4 五景验收表（照搬 ComfyUI 一致性实践）

每个主角出**一版对照表**，五个场景各一张，同一 seed / 同一 LoRA / 同一参考：

| 场景 | 检验什么 |
|---|---|
| 中性胸像 | 基准脸 |
| 四分之三侧 | 小角度变化下的身份 |
| 户外半身 | 光照 + 体型比例 |
| 室内坐姿 | 姿态 + 服装 + 手 |
| 一个小道具场景 | 身份 + 附加需求共存 |

**验收标签只有三个**：`accepted` / `repairable` / `rejected`，并写**具体理由**（"下颌变了" / "身份对，袖子要修" / "眼距不对"）——
比一个模糊的"质量分"可操作得多。

### 3.5 出定妆照用什么工作流

新模板 `workflows/zimage_cast.json`（与场景图分离，理由：定妆照要**比场景图更"标准"**——平光、正视、纯背景）：

| 项 | 定妆照 | 场景图 |
|---|---|---|
| 构图 | 胸像 / 全身三视图 | 16:9 全画幅 |
| 光 | 平光（左右对称补光） | 侧逆光/戏剧光 |
| 背景 | 纯色/素墙 | 场景环境 |
| 尺寸 | 1024×1024 | 1344×768 |
| 批量 | 单人单镜，4 张候选 | 逐镜 1 张（多出候选可选） |

## 四、ComfyUI 一致性编排（三级阶梯，考虑 8 GB 显存）

### 4.1 L1 · 文字锚定（零成本，立刻生效）

**不换模型、不加节点**，只做一件事：**把已审批的 `lock.json.anchor` 作为唯一真源，注入提示词**。

现状：锚定描述抄在 `00-定妆卡.md` 里，人肉复制 → 会漂。
v2：`{NAOKO}` → 从 `lock.json` 取 → **物理上不可能抄错**。

> 这一级就能解决"直子被画成男人"这类问题——记忆里那个 root cause 正是"人物描述以性别词起首 + 个体差异锁定句"，
> 现在它由 `lock.json` 统一管辖，不再依赖人记得写。

### 4.2 L2 · 参考图（img2img 低去噪，最省显存的图像锚定）

新模板 `workflows/zimage_scene_ref.json`：

```
LoadImage(lock.json.primary)  ──►  VAEEncode  ──►  KSampler(denoise=0.45~0.60)  ──►  SaveImage
                                                      ▲
                                   CLIPTextEncode(该镜 prompt + anchor)
```

**为什么选 img2img 而不是 IP-Adapter**：

| 方案 | 8G 显存 | 一致性 | 准备成本 | 结论 |
|---|---|---|---|---|
| img2img 低去噪 | ✅ 够 | ★★★☆ | 零（用定妆照） | **本期选它** |
| IP-Adapter FaceID | ⚠️ 紧（需 InsightFace + 额外权重） | ★★★★ | 中 | 下一期 |
| ControlNet | ⚠️ 紧 | 不控身份 | 需姿态图 | 不用 |
| 角色 LoRA | ❌ 训练要 12G+ | ★★★★★ | 15–30 张 + 云训 | 长期 |

调参顺序（调研结论，别搞反）：
1. **先锁 denoise**（0.45–0.60，太高就换脸，太低就换不出场景）
2. 再调风格词
3. 一次只改一个变量

### 4.3 L3 · LoRA（何时该上）

**触发条件**（满足其一）：
- 该人物跨集出现 **≥ 3 集**
- L2 在真实镜上试片，**连续 3 个镜需要人工重出**
- 要做长期连载

**做法**：用 L2 已批准的定妆照 + 一批高质量场景图攒 15–30 张数据集 → 云训 LoRA（本机 8G 训不了）
→ 参考 `config.toml [comfyui]` 增加 `loras` 段，`workflows/*.json` 挂 `LoraLoaderModelOnly`
→ 权重从 0.70 起调，先锁 LoRA 再开参考图。

### 4.4 工作流模板的目录约定（v2）

```
workflows/
├── zimage_turbo.json            # 场景图 · 纯文生图（现状，保留）
├── zimage_cast.json             # ★ 定妆照 · 平光胸像/三视图
├── zimage_scene_ref.json        # ★ 场景图 · 参考图 img2img（L2）
├── sdxl.json                    # 备用底模
└── _archive/                    # 旧版留档
```

> 模板里**出现的每个 `{{KEY}}` 都必须有默认值**，否则原样留在 JSON 里、ComfyUI 报"节点参数非法"。
> 模型专用采样参数（采样器/步数/cfg/shift）**写在模板字面量里**，代码不含模型知识（D11）。

## 五、G3 生图巡检（把外部脚本的逻辑收进 lvs）

### 5.1 现状与目标

| 现在 | v2 |
|---|---|
| `chain_gen.py` 管续跑与冷却（素材库外部） | `lvs assets` 内置 |
| `check_images.py` 管彩度验收（素材库外部） | 内置，**分块触发** |
| `run_with_heal.py` 管自愈（素材库外部） | 内置，失败单镜自动重出 |
| 人到点了看一眼 | **每 N 张自动巡检一次并落盘报告** |

### 5.2 分块巡检

```
assets 阶段        每 20 张 = 一块
   ├─ 生成中：温控（默认 张间 10s / 每 5 张 90s / GPU ≥80℃ 强制降到 68℃）
   ├─ 块结束：自动巡检  ← ★ 新增
   │    ① 完整性：非零、可解码、尺寸符合预期
   │    ② 彩度：均值 > 5 → 自动 `.convert('L').convert('RGB')`，原图移入 `_fixed/`
   │    ③ 人数：opencv Yunet 人脸检测（`99-工具/models/yunet.onnx` 已有）
   │          - 空镜检出人脸 → 告警（这是 Z-Image 最顽固的失败模式）
   │          - 人物镜检出 0 脸 → 告警
   │    ④ 一致性（L2 启用后）：与 lock.json.primary 的人脸相似度低于阈值 → 告警
   ├─ 异常单镜：自动换 seed 重出（最多 3 次）
   └─ 报告落盘 .work/<task>/qc/qc-block-<n>.json + 汇总到 qc/summary.md
```

### 5.3 为什么必须"定期检查"而不是"跑完再查"

- 挪威线实测：**479 张图跑完 10 小时，才发现整批提示词版本是旧的**（manifest 里还带 `green public telephone booth`）
- 空镜长人、彩度异常，都是**批量性**故障 —— 早 1 块发现，省后面 N 块的浪费
- Z-Image 是 cfg=1.0 蒸馏模型，**换 seed 都救不回来的失败模式**（空镜长人）必须尽早暴露、早改提示词

### 5.4 状态与续跑

```
.work/<task>/
├── manifest.json               # 逐镜：prompt / seed / workflow / prompt_id / bytes / 时间
├── assets/_src/shot-NNN.key    # 请求指纹（已有）
├── assets/local/shot-NNN.png
├── qc/
│   ├── qc-block-001.json       # 每块巡检结果
│   ├── summary.md              # 人读汇总（哪些镜要重出、为什么）
│   └── redo-queue.json         # 待重出队列
└── _stamps/gen.stamp           # 阶段完成戳
```

**续跑语义**：重跑同一条命令 → 跳过已完成、重出队列里的、其余不动。

## 六、全书自动化（一本书 → N 集成片）

### 6.1 三级目录与"事实文件"

参考 Drama Skills 的"**五份 Markdown 即创作事实**"，但我们已有 `.work/` 文件状态体系，所以合并为：

```
D:\fanshu\<书>\10-语料\知识视频素材库\
├── 00-设定/
│   ├── 00-风格与人物定妆卡.md      # 书级唯一口径来源
│   └── 01-旁白音色档案.json
├── 01-素材卡/<NNN>-内容素材包.md
├── 05-拍摄稿/<NNN>-拍摄稿.md       ← 人写/技能产出，格式见《拍摄稿格式契约》
├── 06-分镜提示词/                  # 由 lvs 产出，供人审
├── 07-成片/
├── 99-工具/
└── _cast/                          # ★ 书级定妆库（跨集共享，不在 .work 里）
    ├── lock.json
    └── <NAME>/ref-*.png
```

> **关键**：定妆库放在**书级**而非 `.work/<task>/`。ArcReel 的 Project/Episode 架构同理——
> 第 1 集定好的脸，第 5 集直接引用，"不需要重新描述、重新生成，更不用担心换脸"。

### 6.2 编排器 `lvs book`

```
lvs book init  <书路径>                        # 建 book.yaml + 扫描集清单
lvs book cast  <书路径>                        # 全书人物提取 → 出定妆照 → 等人审（一次性）
lvs book plan  <书路径>                        # 分集计划：哪些集可跑、卡在哪
lvs book run   <书路径> [--ep 001,002] [--to cast|assets|voice|build]
                                               # 逐集推进，遇门禁停下
lvs book status <书路径>                       # 每集每阶段状态 + 待办
```

**门禁不可绕过**：
- `cast/lock.json` 里人物 `state != REF` → **`assets` 拒绝执行**（不是警告，是报错）
- `--yes` 只能跳过"要不要继续"的提示，**不能跳过"未审批"**
- 未审批时 `lvs book run` 打印：

```
✗ EP001 无法继续：直子（NAOKO）的定妆照未批准
  当前 state = IMG（只有提示词，没有图）
  下一步：lvs cast --task NW01            # 出定妆照
          lvs cast --task NW01 --approve NAOKO
  这会保护你：没有冻结的脸，生成的分镜图全都作废（参考 10-01 的 479 张）
```

### 6.3 状态机

```json
// book-state.json
{
  "book": "挪威的森林",
  "style": "jp-youth-manga-bw",
  "episodes": {
    "001": {
      "title": "开篇即结局",
      "script": "05-拍摄稿/001-…-拍摄稿.md",
      "stages": {
        "parse":  {"status": "done", "at": "…", "outputs": ["…/parse.json"]},
        "shots":  {"status": "done", "at": "…", "gates": {"G1": "pass"}},
        "cast":   {"status": "blocked", "reason": "NAOKO 未批准"},
        "assets": {"status": "pending"},
        "voice":  {"status": "pending"},
        "build":  {"status": "pending"}
      }
    }
  }
}
```

**续跑与失败隔离照搬现有 D10 设计**：以文件为状态、幂等、阶段化。
但**审批签名不可被幂等覆盖** —— `lock.json.approved_at` 变更需要显式 `--re-approve`。

## 八、与参考项目的取舍（为什么没照抄）

| 项目 | 值得抄的 | 没抄的 | 原因 |
|---|---|---|---|
| **ArcReel** | 角色设计图优先、人机确认、断点续传、成本预估 | Web UI + 云 API 供应商 | 我们是**本地 ComfyUI**，成本为电费而非 token；引入 Web 栈与现有 `lvs` CLI 冲突 |
| **Drama Skills** | REF-* 三态、五份 Markdown 事实、强制预览确认再生产 | 只做文本层、媒体生成交给外部适配器 | 我们已经有生成层（ComfyUI），要做的是**约束它**而不是外接 |
| **Toonflow** | 角色锚定系统、三层 Agent（决策/执行/监督） | 节点化无限画布 | 画布适合探索，不适合**可复现的批量生产** |
| **SHOTWISE** | 任务队列 + 中断恢复 + 素材版本回滚 | React + FastAPI 全套 | 过重；`lvs` 的文件即状态已覆盖核心 |
| **Pixo** | Project/Episode 共享资产库、Agent 自动 Review | 云端多模型编排 | 我们的"多模型"只有一个：本地 Z-Image |

**共同结论**：真正要抄的只有两条 ——
1. **生成前锁资产**（先定妆，后生产）
2. **生成中设门禁**（每阶段要人签字，机器不许自己往前跑）
