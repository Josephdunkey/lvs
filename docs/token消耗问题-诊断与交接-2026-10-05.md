## §2 根因

### 2.1 核心公式

```
成本 = 调用次数 × 常驻上下文
```

最贵段 178 次调用 × ~10.2 万 token/次 ≈ 18.09 M input。97% 是重读缓存，真产出仅 318 KB。

### 2.2 三个结构性放大因子（源自 token 成本报告，仍成立）

1. **上下文为什么能涨到 9 万+**：前面 9 小时攒下的产物文档全在上下文里每轮重读——审查报告 `docs/*.md`（36 篇 ≈ **33 万 token**）、`shots.json`（11 份 ≈ 84.7 万 token）、大工具输出。
2. **测试无快/慢分层 + 无覆盖率门禁**：导致"看起来没坏"只能靠 agent 反复读代码/重跑测试确认 → 放大重读与调用次数。
3. **`lvs/llm.py` 无注入点**：涉 LLM 的推断只能真调，无法 mock，多轮试探。

### 2.3 本次最贵切片的工作性质

07:09–07:53 在做 **checkpoint#12 收尾——落地「#0 原子写底座 + 变异验证 + 门禁账本」**（对应 commit `4913332`/`33a24fa`）。这段 231 次工具调用 = 212 次 shell 命令，构成：

| 动作 | 次数 | 占比 |
|---|---|---|
| python 探针/杂项（`python -c` 现写） | 50 | 23.6% |
| grep 搜索文件 | 43 | 20.3% |
| 读文件 | 39 | 18.4% |
| git 操作 | 29 | 13.7% |
| pytest 运行 | 19 | 9.0% |
| 读源码（lvs map show） | 12 | 5.7% |
| 变异测试（改→跑→还原） | 10 | 4.7% |
| 列目录 / 续跑摘要 | 10 | 4.7% |

**放大点**：① 每次 `python -c` 现写探针、不复用；② 19 次 pytest 反复跑，未一次跑完该跑的那组；③ 39 次读文件里含整读大文件（`Get-Content` MEMORY.md / 文档），未走 `lvs status --brief`/`map show`；④ 变异验证改→跑→还原 ×10。
