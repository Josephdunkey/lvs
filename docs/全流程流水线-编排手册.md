# 全流程流水线 · 编排手册

> 目标：**给一本书，产出成片**。中间每一步都停一次给人审，有问题当场改，不让垃圾流到下一步。
>
> 这份手册是**执行者（Agent 或人）的剧本**，不是设计说明。设计理由写在每节的「为什么」里。

---

## 一、为什么是"逐环节门禁"而不是"一键全自动"

2026-10 调研了 7 个同类开源项目，共识只有两条。把它们写下来是因为**下一个人一定会想拆掉门禁**，而门禁是这个项目里最容易被误解的部分。

| 来源 | 它做了什么 | 我们采纳了什么 |
|---|---|---|
| **Pixo** 对 50+ 开源流水线的横评 | — | 结论一句话：`one-click output is watchable, not publishable`。跨镜一致性、音画同步、叙事节奏**正是全自动崩掉的地方**；诚实的架构是**逐场景保留人审门**，"一句话出片"的营销话术把这一环抹掉了 |
| **ARIS-Movie-Director** | `each layer consumes the prior LOCKED node, so a skipped step fails closed at the next gate, never shipping a wrong frame` | **fail-closed**：跳过一步 → 下一道门禁的输入没被锁定 → 直接拒绝放行。本项目 2026-10-01 就吃过反面教训（479 张图跑完才发现整批提示词是旧版） |
| **AgentCine** | `OBSERVE → THINK → CHECKPOINT? → ACT → REFLECT`，命中审批节点就暂停等批准/拒绝 | 门禁做成**可查询的状态**（`lvs gate`），而不是散落在各处的 `input()` |
| **Drama Skills**（zenstory-ai，11 步 Agent Skill） | 5 份 Markdown 维护创作事实，**强制预览确认再生产** | 事实落在文件里（拍摄稿 / 定妆卡 / 分镜表），不落在对话里 |
| **Moyin / Toonflow** | 角色设定**先锁定**，后续所有分镜自动引用同一套参考图 | `lvs cast`：先冻脸，再批量出图 |
| **SHOTWISE** | 资产统一管理 + **素材版本回滚** + 中断恢复 | 定妆候选按 `v1/v2…` 版本化；打回不删，移进 `_rejected/` |
| **ArcReel** | 成本追踪 + 编辑草稿 | 门禁挡在"花钱的那一步之前"（拆镜花 LLM、出图花 GPU 小时） |

**一句话**：全自动能做的是"生成"，做不了的是"判断"。所以把生成交给确定性 CLI，把判断交给人，中间用门禁连起来。

## 一点五、这套流水线服务的不止一本书

**一本书 = 一个素材库 + 一份项目 config。** 接新项目是一条命令的事：

```bash
lvs init "D:/fanshu/<书名>/10-语料/知识视频素材库" --name <项目名>
lvs styles --config config.<项目名>.toml        # 30 个画面风格预设，选一个
```

配好 `[paths].lib` 之后，**定妆库 / 定妆卡 / 项目风格文件全部自动派生**，
不用逐个填路径（填错的后果是静默的 —— 定妆库读不到、锚定不注入，不报错）。

| 跟着书走 | 全机共用 |
|---|---|
| 画面风格、定妆库、定妆卡、任务名、拍摄稿与成片 | ComfyUI 地址与模型、TTS 服务、API key、人脸权重 |

画面风格有 30 个内置预设（`lvs styles` 看全部，按题材分组、标注是否单色），
也可以给某本书写专属风格（`<素材库>/00-设定/风格预设.toml`）—— **不需要改代码**。

> 完整接入流程与常见错误见 **`docs/新项目接入指南.md`**。

## 二、流水线全景

```
  书（原著 + 分章文本）
      │
      │  ① 拆书 —— newmuyu 技能（Agent 做，不是代码）
      ▼
  拍摄稿.md ────────────────────────────────────┐
      │                                          │
      │  ② lvs check    结构和否定式体检          │
      │  ③ lvs migrate  补 [场景]/[人物槽位]/代词  │
      ▼                                          │
 ┌──────────────┐                                │
 │  ⛔ G0 拍摄稿 │◀── 人审（这一步错了后面全废）─┘
 └──────┬───────┘
        │  ④ lvs parse → lvs shots（花 LLM 钱）
        ▼
   shots.json（拆镜 + 每镜提示词）
        │
 ┌──────────────┐
 │ ⛔ G1 分镜与提示词 │◀── 人审（提示词定死画面）
 └──────┬───────┘
        │  ⑤ lvs cast   定妆：提取 → 出候选 → 审阅表 → 批准冻结
        │
 ┌──────────────┐
 │  ⛔ G2 定妆参考 │◀── 人审（没有冻结的脸，跨镜必然变脸）
 └──────┬───────┘
        │  ⑥ lvs assets（花 GPU 小时）＋ 每 24 张跑一次 lvs qc
        ▼
  分镜图 + 巡检报告
        │
 ┌──────────────┐
 │ ⛔ G3 分镜图与巡检 │◀── 人审（这一批图能不能用）
 └──────┬───────┘
        │  ⑦ lvs voice（配音 + 字幕）
        ▼
  音轨 + subtitle.srt
        │
 ┌──────────────┐
 │  ⛔ G4 配音与字幕 │◀── 人审（音画同步、字幕错行，合成后返工最贵）
 └──────┬───────┘
        │  ⑧ lvs build（ffmpeg 合成）
        ▼
  final.mp4
        │
 ┌──────────────┐
 │   ⛔ G5 成片  │◀── 人审（时长 / 音画 / 字幕 / 署名 / 引用合规）
 └──────┬───────┘
        ▼
     交付
```

**门禁的粒度选择**：不放在阶段**之后**（那只是追认），放在阶段**入口**（那才拦得住花钱）。
唯一的例外是 G5 —— 它没有下游，是终审。

**`lvs parse` 不受门禁约束**：它免费、可逆，且它的产物正是 G0 的审阅对象。

## 三、六道门禁

| 门禁 | key | 守什么 | 挡的是哪一步 | 为什么必须停 |
|---|---|---|---|---|
| **G0** | `script` | 拍摄稿：结构、否定式、人物槽位 | 拆镜（LLM 花钱） | 稿子写错，后面几百张图全部作废（2026-10-01 实测）。改一个字比重跑十小时便宜 |
| **G1** | `shots` | 拆镜结果 + 每镜提示词 | 出图（GPU 小时） | 提示词定死画面。跑之前必须看：镜数、有没有跑偏、有没有旧版残留 |
| **G2** | `cast` | 人物脸已冻结并批准 | 出图 | 没有冻结的脸，跨镜必然变脸 —— 不是概率问题 |
| **G3** | `images` | 全部图 + 巡检结论 | 配音 | 出图最贵。要在**过程中**巡检（每块 24 张过眼），别等全跑完才发现整批崩 |
| **G4** | `voice` | 逐镜音轨 + 字幕 | 合成 | 音画不同步、字幕错行，合成之后返工成本最高 |
| **G5** | `final` | `final.mp4` 终审 | 交付 | 时长 / 音画 / 字幕 / 片尾署名 / 引用合规 |

### 命令

```bash
lvs gate --task NW01P1                      # 现状：哪道门开着、下一道是哪道
lvs gate --task NW01P1 --next                # 只打印下一步该看什么
lvs gate --task NW01P1 --json                # 机器可读（Agent 用）
lvs gate --task NW01P1 --approve G0 --note "稿子OK"
lvs gate --task NW01P1 --reject  G1 --note "第 12 镜提示词跑偏"
lvs gate --task NW01P1 --skip    G3 --note "纯空镜集，无需看图"
lvs gate --task NW01P1 --reset   G1          # 改完东西打回重审
```

### 核心机制：**指纹绑定**（这是这套门禁唯一不可省的地方）

只记「G0 已批准」是不够的 —— 批准的是**某一版**稿子。稿子事后被改了，
"已批准"就变成一句谎言。所以：

- 每次批准都记下**当时批准对象**的指纹（`relpath|size|mtime_ns` 的 sha1）
- 校验时重算：指纹不符 → 该门禁**自动回到未批准**，并显示「批准时 N 文件 → 现在 M 文件」

这就是 fail-closed 的落地：**宁可让你重审一次，也不放过一版没人看过的产物。**

> 指纹用 `size + mtime_ns` 而不是内容哈希，是刻意取舍：G3 的对象是几百张图，
> 逐张读内容要几秒，只 stat 是毫秒级；任何真实写入都会改 `mtime_ns`。
> 代价是复制/恢复文件也会判 stale → 多问一句「请重审」，这是**安全方向**的误报。

### 打回和跳过都必须写原因

`--reject` / `--skip` 不给 `--note` 会被**直接拒掉**。理由：没有原因的打回，下游只能靠猜，
而猜错的代价是重跑一遍；跳过会记进账本（谁、何时、为什么），留痕是为了让"跳过"这件事可追溯。

## 四、逐步操作

### ① 拆书 → 拍摄稿（Agent 做）

用 `newmuyu` 技能。产物落到 `<书名>/10-语料/知识视频素材库/05-拍摄稿/NNN-<期名>-拍摄稿.md`。

**格式契约见 `docs/拍摄稿格式契约.md`**。本手册只强调三件与门禁相关的事：

1. **画面位要写 `[场景]` / `[图表]` 标注** —— 解析器靠它分流（本地生图 vs 本地排版卡片）
2. **人物要写 `{ID}` 槽位**，或至少写全名（`lvs migrate` 能从定妆卡把全名换成槽位）
3. **代词在集内唯一时，在稿件头部声明一行**：
   `> 代词：她={NAOKO}，他={渡边彻}`
   代词是**集级**信息 —— 《挪威的森林》里「她」书级有四个候选（直子/绿子/初美/玲子），
   但在 P1 里只指直子。写成一行比让每个人每集猜一次便宜得多。

**拆书的检查点（技能自带）**：拆期方案 + 每期一句话立论 + 覆盖哪几章，**先给用户确认再写正文**。

### ② 稿件体检 + 迁移

```bash
lvs check  <拍摄稿.md>                                  # 只读，不改稿
lvs migrate <拍摄稿.md>                                 # 产物落 _v2/，绝不覆盖原稿
```

> ⚠ **顺序陷阱（踩过）**：`migrate` 是**从原稿重新生成** `_v2/`。
> 所以对 `_v2/` 做过的任何手工修改（比如否定式改写），**再跑一次 migrate 就没了**。
> 正确顺序：`migrate` → 人工/脚本改写否定式 → `mv _v2/* 替换原稿`（或固定以 `_v2/` 为准，不再重跑 migrate）。

`lvs migrate` 做三件机械的事、列两件需要人判断的事：

| 做 | 补 `[场景]/[图表]` 标注 ｜ 把人物名换成 `{ID}` 槽位 ｜ 把代词换成 `{ID}`（唯一才换） |
|---|---|
| 列给人 | **否定式描述**（`无字`/`空无一人`）｜**有歧义的代词** |
| 列给人复核 | **疑似比较提及**（「与渡边彻龄」和「与渡边彻并肩」句式相同，机器分不清） |

### ③ 定妆（G2 的实体）

```bash
lvs cast --task NW01P1 --lint          # ★ 先体检锚定描述，改定妆卡
lvs cast --task NW01P1 --extract       # 从定妆卡 + 拍摄稿建库
lvs cast --task NW01P1 --render ALL --count 4
lvs cast --task NW01P1 --sheet         # 一张图看完所有候选
```

**`--lint` 是这一步最值钱的命令**，它检查锚定描述里"不可画的写法"：

| 判据 | 为什么 |
|---|---|
| `A-order` 第一小句没有可画的骨相词 | cfg=1.0 的模型对**前段**权重更高。开头放"一个活泼的大学生"会把采样预算花在气质而不是脸上（MIDORI 因此长出长发盖住耳朵） |
| `A-nosubject` 整段没有人称名词 | 为把特征前置，很容易**连主语一起丢掉** —— 模型于是自己决定画谁（第一版 MIDORI 被画成了**男性**）。推荐写法：**主语 + `with` + 特征** |
| `A-procedure` `hair cut short` | 写的是**动作**不是结果。改成 `ears and nape fully exposed` |
| `A-measure` `four or five centimetres` | 模型画不出度量。改成物理属性 |
| `A-expression` `a faintly cool smile` | ★ 表情是**逐镜变**的，混进锚定会让五官跟着一起重采样 —— **同一段锚定出四张脸**（木月四张候选像四个人就是这个） |
| `A-diluted` 服装道具词 ≥ 骨相词 | 不只是脸会飘，**构图也会被带跑** —— 突撃隊的锚定列了 5 件衣物，出图直接变成全身站姿，与「中性胸像」打架 |
| `A-simile` `seem to` / `as if` | 模型按字面画 |
| `A-bloated` 超过 55 词 | 属性会被**逐条独立采样**，长锚定 = 更多自由度 = 更不像 |
| `A-neg:*` 否定式 | 与 `lvs check` / `lvs migrate` **同源**（`prompting.NEGATION_RULES`） |

**为什么 lint 值得单独一步**：锚定描述是「跨镜不变的那张脸」的唯一来源。它写得不可画，
后面几百张图会一起歪 —— 而这类问题**看代码看不出来，看四张候选也只会觉得"随机性真大"**，
不会想到是锚定写法的问题。

> ⚠ **lint 通过 ≠ 图对**。本轮最贵的一个错误（锚定丢了主语、MIDORI 被画成男性）
> lint 当时全绿、测试全绿、提示词打印出来也读得通 —— **只有看图才发现**。
> 定妆这一步的验收动作永远是**看图**，lint 只是把明显错误的写法提前筛掉。

### ④ 拆镜与提示词（G1 的实体）

```bash
lvs parse --task NW01P1 <拍摄稿.md>
lvs shots --task NW01P1              # 花 LLM 钱
lvs gate  --task NW01P1 --approve G1 --note "镜数与提示词看过"
```

### ⑤ 出图与巡检（G3 的实体）

```bash
lvs assets --task NW01P1             # 花 GPU 小时；定妆闸门会先拦一道
lvs qc     --task NW01P1 --block 20  # 每出满一块跑一次增量巡检
lvs gate   --task NW01P1 --approve G3
```

`lvs qc` 一次给三样：硬指标清单（彩度/完整性/人数）、缩略网格（一次性过眼 24 张）、高风险镜标签
（极特写空镜 / 单人镜 / 多人镜 —— 崩坏高发区）。

> ⚠ **别为质检引入重型依赖**。本项目试过 OpenCV YuNet 人脸计数，踩了一串坑
> （cv2 5.0 移除 Haar API、ONNX 导入器读不了 YuNet、降级后下载文件损坏），耗时 20+ 分钟无果。
> **「缩略网格 + 人眼」才是这个任务下最高效的质检手段。**

### ⑥ 配音 / 字幕 / 合成（G4、G5）

```bash
lvs voice --task NW01P1              # 逐镜配音 + subtitle.srt
lvs build --task NW01P1              # ffmpeg 合成 → final.mp4
lvs gate  --task NW01P1 --approve G5 --note "成片OK"
```

**GPU 串行守卫**（`lvs guard`）：8 GB 显存下本地生图与本地 TTS **不能同时驻留**。
守卫在阶段入口探测对端服务，冲突时明确报错并说明停哪个 —— 绝不自动抢占、绝不静默降级。

### ⑦ 投稿物料（B站 / 抖音）

```bash
lvs publish --task NW01P1 --config config.挪威的森林.toml
lvs publish --task NW01P1 --out "D:/fanshu/…/08-投稿"   # 顺带拷进书库留档
```

产物落在 `.work/<任务>/publish/`：`cover-bilibili.png`(1344×768) /
`cover-douyin.png`(1080×1920) / `bilibili.md` / `douyin.md` / `meta.json`。

三条设计约定，改的时候别弄丢：

1. **封面三行字一律取拍摄稿 `【封面文案】`**（`行1/行2/行3`，按编号排序）。
   工具**不编封面字** —— 编了就等于绕开"文字锚定"这一层校验。
   稿子没写封面文案时才降级到【标题】卡，并在产物里给警告。
2. **缺东西只降级、不阻断**：没有 `final.mp4` → 少报时长 + 一条警告；
   没有可用画面 → 纯靛蓝渐变底，字照叠（**不假装**有画面）。返回码仍是 0。
3. **幂等**：文案是纯函数、PNG 不写时间戳，所以**没有 `--force`**；
   底图换了直接再跑一次即可（`--base` 可换底图）。

发布前还有一份人工清单：`docs/发布前检查清单.md`。

## 五、断点续跑与失效重审

```bash
lvs run --task NW01P1 <拍摄稿.md>     # 走一步、停一道门；再跑一次就从原地继续
```

`lvs run` 的语义是 **"执行到下一道门为止"**：

1. `parse`（免费，不受门禁约束）
2. 检查 G0 → 未批准就停下，打印「下一道要过的门：G0·拍摄稿」+ 三条命令
3. G0 批准后重跑 → 走 `shots`，停在 G1
4. …依此类推

**逃生门**：`--skip-gates`（本次不检查、不记账）或 `[pipeline].enforce = false`（配置级关闭）。
默认**生效** —— 关掉人审必须是一次显式动作。

**失效重审**：改了稿子/分镜/定妆卡之后，对应门禁自动变 `⚠️ 已失效`，`lvs run` 会停在那里
并显示「批准时 N 文件 → 现在 M 文件」。不放心就 `--reset` 手动打回重审。

## 六、血泪清单（每一条都是真踩过的）

1. **改了定妆卡却没重跑 `--extract`** → 库里的锚定还是旧的，出图照用旧脸。改完锚定**必须**重跑 extract。
2. **`migrate` 覆盖 `_v2/` 的手工改写** → 见 §四②的顺序陷阱。
3. **简称漏槽位**：画面位写「渡边」而库里只有「渡边彻」→ 那一镜**根本不注入锚定**，且不报错。
   别名要写全（定妆卡标题括号里写 `渡边彻（わたなべ / 渡边 / "我"）`）。
4. **短别名截断全名**：`渡边` ⊂ `渡边彻`。槽位必须**长名优先 + 不在已生成槽位内匹配**。
5. **代词误伤复合词**：`其他` / `他们` / `自我` 会被当成代词换掉。边界判据必须拿**原文**判，
   且空串不能当"命中"（`"" in 任意串` 恒为真 —— 句首代词会被全部挡掉）。
6. **比较提及**：「与渡边彻龄」被当成出场 → 把渡边的锚定注进了木月的镜。机器分不清就列给人复核。
