# 调研：模型选型（8GB 显存）与 ComfyUI 人物一致性

> 2026-10-03 夜。机器：RTX 4060 Laptop · **8GB 显存** / 16GB 内存。
> 前提约束：**换模型不能比 Z-Image 出图效果差很多**（Z-Image Turbo 是当前主力，观感达标）。

---

## 一、这台机器能带动什么生图模型

### 1.1 主力 Z-Image Turbo（6B，Apache 2.0）——不换的理由

| 精度 | 显存占用 | 结论 |
|---|---|---|
| BF16 | ~14–16 GB | ❌ 8GB 装不下 |
| FP8 | ~8 GB | ⚠️ 勉强（与 ComfyUI 自身争抢，实测是现在 int8 变体的路线） |
| **GGUF Q5_K_S** | **<6 GB** | ✅ **甜点位**：留得出余量，质量损失可忽略 |
| 当前 int8 convrot | ~6–7 GB | ✅ 现役方案，8 步出图 |

结论：**Z-Image 自己还有余量可挖**（想省显存/提质量可试 GGUF Q5），没有换模型的紧迫性。

### 1.2 竞品横评（都以"8GB 能跑 + 质量不输 Z-Image"为门槛）

| 模型 | 参数量 | 8GB 可行性 | 质量对比 Z-Image | 生态（一致性方案） | 结论 |
|---|---|---|---|---|---|
| **Z-Image Turbo**（现役） | 6B | ✅ FP8/GGUF | 基准 | 弱（无官方 IP-Adapter） | **继续用** |
| FLUX.2 klein | 4B | ❌ FP8 也要 ~13GB | 疑似更好 | 中 | 超显存，出局 |
| Qwen-Image 2.0 | - | ⚠️ fp8 ~8–12GB | 接近/略逊 | 中（阿里系持续更新） | 备选，但没有必须换的理由 |
| SDXL base | 3.5B+3B | ✅ | **明显逊**（2020 年代初水平） | **最强**（IP-Adapter/InstantID/PuLID 全家桶） | 质量门槛过不了，出局 |
| Z-Anime（同生态变体） | 6B | ✅ 同 Z-Image | 同源 | 同 Z-Image | 动漫题材可试，同生态零迁移成本 |

**结论：现阶段不换模型。** Z-Image 在 8GB 甜点位上没有对手——比它好的跑不动，跑得动的不如它。
真正值得做的是补齐它的短板（一致性），以及榨取 GGUF 档的显存余量。

## 二、ComfyUI 人物一致性：能做，分三档

### 2.1 三档阶梯与本项目现状

| 档 | 方法 | 一致性强度 | 本项目状态 |
|---|---|---|---|
| L1 | 文字锚定（`{NAME}` → lock.json.anchor） | 弱（提示词祈祷） | ✅ 已落地 |
| L2 | 参考图 img2img（冻结定妆照喂进去） | 中 | ✅ **已补齐 + 真机验证**（2026-10-03） |
| L3 | 角色 LoRA / FaceID 类 | 强 | ❌ 未做（见下） |

L2 的三块拼图已全部接通：`upload_image()`（ComfyUI 只认自己 `input/` 里的文件）→
`generate(ref_image=…)` → `workflows/zimage_scene_ref.json`。旋钮 `[cast].ref_denoise`（默认 0.55）。

### 2.2 L3 路线调研（Z-Image 的特殊困难）

★ **Z-Image 没有官方 IP-Adapter** —— 这是选它时没付、现在要付的账：

| 方案 | 对 Z-Image 可用性 | 说明 |
|---|---|---|
| IP-Adapter FaceID | ❌ 需社区转换权重（Boyonodes 有，难找/难验证） | SDXL/SD1.5 生态成熟 |
| InstantID | ❌ 同上，依赖 ControlNet+IPAdapter 双件 | SDXL 专属 |
| PuLID | ❌ 有社区 Z-Image 尝试，未见稳定工作流 | 权重经验值 PuLID 0.8 |
| **Face LoRA** | ⚠️ 理论可行（任何 DiT 都能训） | 本机 8G **训不了**，需云训 |
| **L2 img2img（现役）** | ✅ | denoise 0.45–0.60 区间已验证 |

**经验权重参考**（若将来云训/换生态）：PuLID 0.8、InstantID 0.8/0.5（face/context）、IP-Adapter FaceID 0.85。

**建议路线**：L2 + 已批准定妆卡（G2 门禁）已经能压住大部分跨镜漂移；
真要上 L3，**云训 Face LoRA 是唯一不换模型的路**，等 L2 不够用时再上。

### 2.3 巡检侧的洞见（本次夜修已闭合）

- `lvs qc` 查的是人脸**数量**（Q006 空镜长人 / Q007 人物镜没脸），**不是身份一致性**——
  全仓无 embedding/相似度校验，跨镜一致性只靠 L1+L2。
- Q006/Q007 曾"静默死"（cv2 读不了中文路径 → 权重加载失败）——**已修**：
  `_ascii_cache_copy` 中文路径转 ASCII 缓存 + doctor 检查项 + 大声报错。
  60 张样本实测：0 脸 18 / 1 脸 32 / 多脸 10，背影判对，小侧脸有漏检（warn 级，不卡门禁）。

## 三、多模态批量看图巡检（已落地：`lvs qc --sheet`）

用户提议："每出 30 张图，模型做一次检测，可以缩略图省 token，有问题的自动改。"

**实现**：`lvs qc --sheet` 生成带镜号的缩略图拼版
（`.work/<任务>/qc/contact-sheet-NN.png`，**30 张/页**对齐"每 30 张巡一次"）：

- 缩略图 320×180 + 镜号条**分色**：🔴 红=error / 🟡 黄=warn / 🟢 绿=通过 / ⚪ 灰=缺图
- **颜色就是结论**：多模态模型看一张图、报一串镜号即可，不用复述问题描述 → 省 token
- 分页、乱序喂入按镜号排、缺图/坏图占位灰格（镜号不错位）、无 PIL 降级不阻断
- 13 项测试 + 3 个突变全部变红验证（排序/三态色/占位格）

省 token 效率：30 张原图（1344×768）≈ 3–6 万 token → **1 张拼版 ≈ 1–2 千 token**，约 20–30 倍。

**待接线（下一步）**：模型看图点名 → `lvs assets --only <镜号>` 重跑坏镜。这是"有问题自动改"的闭环，需要一个 agent 工作流把两步串起来。

## 四、NarratoAI 参考点（已吸收）

[linyqh/NarratoAI](https://github.com/linyqh/NarratoAI) 是同类"小说→视频"工具，值得抄的两条：

1. **BGM 混在成片音轨之下、失败只记日志绝不中断成片** → 已进 `build.finalize`：
   配了 `[bgm].file` 就循环铺满旁白 + 低音量（0.25）+ 首尾淡入淡出；
   任何 `FFmpegError` **自动退回无 BGM 版本**并打印原因。
   ★ `amix` 必须 `normalize=0`（ffmpeg ≥4.4 默认把各输入各除以输入数 → 旁白砍半）。
2. 成片终检思路（音轨存在性/音量/黑屏占比）——本项目 `final_sanity` 已有同款。

新增配置（`config.example.toml`）：

```toml
[bgm]
file = ""          # 留空 = 不加；填 mp3/wav/m4a 路径
volume = 0.25      # 0–1，旁白为主 BGM 为辅
fade_in = 2.0      # 淡入秒数（0 = 关）
fade_out = 3.0     # 淡出秒数（0 = 关）
```

测试：18 项（三态/滤镜串/退回外壳/两条混音路径 normalize=0/真 ffmpeg 端到端）
+ 2 个突变（去 normalize=0、去退回外壳）全部被抓。
