## B00 · 更正：`final.mp4` 那条，"没有任何门禁能识别它"说重了

主报告 §2.1 与票据 47 的说法需要收紧，否则会误导修复方向：

- **实际是**：`build.run_command` 收尾有 `assert_segment_rendered(final, final_dur)`
  （`build.py:770`），`final.mp4` 缺 moov 时 `ff_duration()` 返回 `None` → `0.0`
  → 抛 `BuildError` → 打印"成片校验失败"并 **返回 2**。所以**正常异常路径**下
  不会"把坏片当成功"。
- **真正没防护的是两条**：
  1. **进程被杀（SIGKILL / 断电 / 关窗口）**：没有收尾检查的机会，坏文件留在盘上；
  2. **坏文件不被删除**：下一轮 `build` 在 `finalize` 写盘前不会先删它，而
     `07-成片/` 的拷贝是**手工**动作（无校验）—— NW03 那次就是这样把 235 MB 的死片带进交付目录的。
- **结论不变，措辞要准**：修法仍是"`.part` → `os.replace` + 失败即删除半成品 + 拷贝前校验"，
  但**不要**按"门禁看不出来"去做（那会让你去改门禁，改错地方）。

```python
# lvs/build.py · _finalize()：三条路径（烧字幕 / 混 BGM / 直出）都要落 .part
    out = ws.path("final.mp4")
    part = out.with_name(out.name + ".part")
    part.unlink(missing_ok=True)
    try:
        ...  # 三处 ff_run 的 str(out) 全部换成 str(part)
        part.replace(out)          # ★ 原子落定
    except BaseException:          # ★ KeyboardInterrupt 也要删半成品
        part.unlink(missing_ok=True)
        raise
```

- **文件**：`lvs/workspace.py:227`（`seen = int(data.get("version") or 1)`）、

- **实际**：`json.load` 的语法错误被接住了，但**结构**问题没有。`version` 一旦不是纯整数

  从 `_read_manifest` 一路冒到 `cli.main` 的兜底 → **"内部错误"+ 退出码 1**。
- **实测（`.work/tmp/_probe_manifest2.py`）**：

  CRASH "version": "v2"（手改）   -> ValueError: invalid literal for int() with base 10: 'v2'
  OK    "version": null          -> version=1
  ```

- **风险**：`Workspace.ensure()` 是所有任务级命令的必经之路 → **该任务的 `parse/shots/assets/

# lvs/artifact.py 新增（B04/B17 共用）
def as_int(value: Any, default: int = 0) -> int:
    """宽松取整：认 int / "12" / "1.0"；其余返回 default。

    ★ 为什么不能裸 `int()`：这些值来自**人手改过的 json 与 config**。
    裸 int() 抛的 ValueError 会被 `cli.main` 归成"内部错误 + 退出码 1"，
    而正确语义是 2（改了再来，**别自动重试**）—— 脚本据此决策会一直重试。
    实测：manifest 的 `version` 写成 "0.2" 时，该任务的所有命令全部打不开。
    """
    try:
        return int(value)
    except (TypeError, ValueError):
        try:
            return int(float(value))
        except (TypeError, ValueError):
            return default
```

def read_manuscript(path: Path) -> str:
    """读拍摄稿：**先按证据认编码，再不行给一句人话**。

    实测：GBK 的稿子会让裸 `read_text("utf-8")` 抛 UnicodeDecodeError，
    被 `cli.main` 归成"内部错误"+退出码 1 —— 那是用户的第一条命令，
    不该用这句话劝退他。
    """
    raw = path.read_bytes()
    if raw[:2] in (b"\xff\xfe", b"\xfe\xff") or raw[:3] == b"\xef\xbb\xbf":
        return raw.decode("utf-16" if raw[:2] in (b"\xff\xfe", b"\xfe\xff") else "utf-8-sig")

        return raw.decode("utf-8")
    except UnicodeDecodeError:
        pass
    try:
        text = raw.decode("gb18030")
    except UnicodeDecodeError as exc:

            f"拍摄稿读不出编码：{path}\n"
            f"  已试过 UTF-8 / GB18030。请用编辑器另存为 UTF-8 后再跑。\n  原因：{exc}"

    return text

```python

def timeline_problems(shots: list[Any]) -> list[str]:
    """时间轴自检（**只给 build 用** —— 它是唯一消费 `start`/`end` 的阶段）。

    为什么单列一条而不并进 `validate_shots`：`assets`/`voice` 根本不用时间轴，
    拿它去卡这两个阶段是**误报** —— 而校验器的价值全在报得准（本模块反复强调过）。
    """
    out: list[str] = []
    prev_end = -1.0
    for s in shots:
        if not isinstance(s, dict):
            continue
        sid, start, end = s.get("id"), s.get("start"), s.get("end")
        if start is None or end is None:
            out.append(f"`id={sid}` 缺 `start`/`end`（配音没成功，或手改漏了）")
            continue
        try:
            a, b = float(start), float(end)
        except (TypeError, ValueError):
            out.append(f"`id={sid}` 的 `start`/`end` 不是数字：{start!r} / {end!r}")
            continue
        if b - a < 0.05:
            out.append(f"`id={sid}` 时长 {b - a:.3f}s ≤ 0（start={a} end={b}）—— build 会夹成 0.2s 闪一帧")
        elif a < prev_end - 0.001:
            out.append(f"`id={sid}` 的 start={a} 早于上一镜 end={prev_end}（时间轴不单调）")
        prev_end = max(prev_end, b)
    return out
```
