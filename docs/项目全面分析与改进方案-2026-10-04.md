### 1.4 必须保留的设计（先说好话，这些别动）

1. **`stage.py` 是阶段顺序的唯一真源**，`tests/test_architecture.py` 有 25 个测试守着。
   我一个下午的改动里它真的抓出过一次"阶段顺序出现第 6 份副本" —— 这条护栏是有效的。
2. **退出码有语义**（`errors.py`）：`2` = 输入错（别重试）、`3` = 等人审（等，不是错）。
   把"正常流程的一部分"和"真出错了"分开，是自动化能被信任的前提。
3. **指纹绑定门禁**：防的是"批的是 A 版、跑的是 B 版"这种最贵的错误。
4. **`net.py` 绕 localhost 代理**：国内 Clash/v2ray 环境下的真实血泪，注释里记了对照实验。
5. **逐镜失败隔离 + 连续失败熔断**：654 镜不会因为服务挂了一镜一镜地超时到底。
6. **降级不阻断的取舍是明确的**：BGM 坏了退回无 BGM、烧字幕失败退回无字幕版，
   而且**都打印原因**。这比"失败就整体崩"和"静默吞掉"都好。

### 🔴 2.1 `build` 非原子写 `final.mp4`：中断留下"大小正常但打不开"的成片

- **文件**：`lvs/build.py:558`（`out = ws.path("final.mp4")`，三处 `ff_run(... str(out))`）
- **证据**：票据 `.scratch/.../issues/47-build-non-atomic-final.md` 仍为 `Status: open`（实测 NW03 出过 `moov atom not found` 的 235 MB 死文件，且**被拷进了 `07-成片/`**）。
- **风险**：ffmpeg 被 Ctrl-C / 崩溃 / 断点续跑被 kill 时，`ftyp + mdat` 已落盘、`moov`（写在文件尾）永远没写。文件大小正常、`ffprobe` 打不开，**没有任何门禁能识别它**。而 manifest 因为进程非正常退出，`stages.build` 是空的 —— 下次跑若只判"文件存在"就当成功跳过。
- **修法**（先写 `.part`，成功再原子改名；`os.replace` 在 Windows/POSIX 都保证原子）：

```python

    part = out.with_name(out.name + ".part")   # ★ 半成品只写这里
    part.unlink(missing_ok=True)               # 上一轮被 kill 留下的残骸

    # 三处 ff_run 的 "str(out)" 全改成 "str(part)"，每次成功返回前补一行：
    #     part.replace(out)   # 原子落定：读方要么看到旧的，要么看到完整的
```
```python
# 调用侧（build 主流程）在 finalize 之后加一道"复读"兜底（项目已有同名直觉：
# `assert_segment_rendered`）：

    final_dur = ff_duration(final) or 0.0
    assert final_dur > 0, f"成片不可解析（moov 缺失？）：{final} —— 判定失败，别当成功"

> 三条都要落 `.part`，否则只修一条等于没修。

- **文件**：`lvs/tts.py:720` `_audio_reusable()`（只比 `voice` 与 `text_sha1`）
- **证据**：`config.toml` 里 `rate = "-12%"`、`pitch = "-25Hz"` 都真实存在；票据 46 `Status: open`。
- **风险**：改语速/音高/后端而**文本与音色名不变**时 → 判定"可复用" → 旧 mp3 与旧 `norm/*.wav` 一起沿用，
  **全程零报错**。用户以为改生效了，实际听到的还是上一版。（票据 46 记录过同族事故：
  整轨 1083 s vs 时间轴 1168 s，`build -shortest` 截掉 65 s，音画字幕整体漂移。）

                   "tts.volume", "tts.instruct", "tts.language", "tts.ref_audio",
                   "tts.ref_text", "tts.xvec_only", "tts.base_url",

### 🟠 2.3 门禁账本非原子写：截断 → 6 道门的批准记录全丢

- **文件**：`lvs/pipeline.py:271` `p.write_text(json.dumps(led.to_dict(), ...))`
- **对照**：`lvs/workspace.py` 的 `_write_manifest()` 已经写了完美的三段式（临时文件 → `fsync` → `os.replace`），
  注释里把理由讲得清清楚楚。**同一个仓库里，一条写路径修了、另一条没修。**
- **风险**：`gates.json` 被截断时 `load()` 会退化成**空账本 = 全部未批准**。
  方向是 fail-closed（安全），但代价是用户要**重审 6 道门**（其中 G3 是 400 张图的人眼巡检）。
- **修法**：把原子写抽成公共函数，两处共用（见 §10-A2）：

```python
# lvs/artifact.py 新增
def atomic_write_text(path: Path, text: str, *, encoding: str = "utf-8") -> None:
    """原子写文本：临时文件 → fsync → os.replace。`_write_manifest` 的同款做法，
    抽出来给所有"写坏了就得重来"的产物用（manifest / gates.json / shots.json / srt）。
    """
    path.parent.mkdir(parents=True, exist_ok=True)
    tmp = path.with_name(path.name + ".tmp")
    with open(tmp, "w", encoding=encoding, newline="\n") as fh:
        fh.write(text)
        fh.flush()
        os.fsync(fh.fileno())
    os.replace(tmp, path)          # 同文件系统上原子
```

### 🔴 4.1 API key 明文落盘，且代码**只**认文件这一条路

- **文件**：`config.toml:10` → `openai_api_key = "sk-203a…2556"   # 已掩码；真值见 config.toml（不要抄进任何文档/票据）`
- **已核实的两件事**（不要误判严重性）：
  1. `config.toml` 在 `.gitignore` 里，且 `git log --all -- config.toml` **为空** → **未进 git 历史**；
  2. `lvs/doctor.py:138` 只打印 `已配置（provider/model/base）`，**不回显 key**；
     `lvs/gui/configio.py:149` 对 `secret` 字段走 `mask()` → **GUI 也不回显**。
- **仍然成立的风险**：全仓库 `os.environ` 只用于 `LVS_CONFIG` / `LVS_BROWSER` / `LVS_DEBUG`（已 grep 核实），
  **没有密钥环境变量通道** → 用户被逼着把 key 写进文件。一旦 `config.toml` 被同步/备份/打包/截图，
  key 就跟着走；`config.<书>.toml` **不在** `.gitignore` 里（`lvs/project.py` 生成），
  如果哪天有人把密钥复制进去，就会直接入库。
- **修法**（三件小事，成本极低）：

```python
# lvs/config.py · 新增环境变量覆盖层（env 优先于文件）
_SECRET_ENV = {
    "app.openai_api_key": "LVS_OPENAI_API_KEY",
    "pexels.api_key": "LVS_PEXELS_API_KEY",
}


def _apply_env_overrides(data: dict[str, Any]) -> dict[str, Any]:
    """密钥类字段允许被环境变量覆盖：`app.openai_api_key` ← `LVS_OPENAI_API_KEY`。

    为什么必须有：此前代码里**只有配置文件这一条路**（grep `os.environ` 只有
    LVS_CONFIG / LVS_BROWSER / LVS_DEBUG），等于把用户逼进"把 key 写进磁盘明文"。
    """
    for dotted, env_name in _SECRET_ENV.items():
        value = os.environ.get(env_name)
        if not value:
            continue
        section, leaf = dotted.split(".")
        node = data.setdefault(section, {})
        if isinstance(node, dict):
            node[leaf] = value
    return data
```
```python
# lvs/config.py:196（唯一的 return cls(data, path)）
-        return cls(data, path)
+        return cls(_apply_env_overrides(data), path)
```
- 配套：`config.toml` 里把那把 key 换成 `openai_api_key = ""` 并在注释里写
  `# 优先用环境变量 LVS_OPENAI_API_KEY；写在这里会被同步/备份带走`；
  **建议轮换一次**这把 key（明文在盘上存在过，暴露面无法穷举）。

# lvs/workspace.py · _read_manifest() 的重建分支
    except json.JSONDecodeError:

        try:
            shutil.copy2(self.manifest_path, backup)   # ★ 先留证，别覆盖

              f"断点续跑记录丢失，本任务会从检查点重做。")
        return {}

## 8. 专项研究：为什么"光是继续往下做"就这么费 token？

> 逐轮重发机制与整场会话的拆账，见 [`token成本研究报告-2026-10-05.md`](token成本研究报告-2026-10-05.md)。
> 这一节是本次分析里**最该被行动**的部分。结论先行：
> **项目没有为"续跑 agent"这个主要用户做任何上下文减法。**
> 每次继续做，agent 都要重新回答"我在哪、下一步干嘛、真相源是哪份"，
> 而这个回答目前只能靠**把几百 KB 文本读进上下文**得到。

### 8.1 实测：一次"我接着做"要读多少东西

| 文件 | 大小 | 行数 | 谁在读 |
|---|---|---|---|
| `AGENTS.md` | 1.7 KB | 26 | 每轮（自动） |
| `.workbuddy/memory/MEMORY.md` | 7.4 KB | 86 | 约定唯一权威 |
| `.workbuddy/memory/2026-10-03.md` | **63.3 KB** | **916** | 当日进展（流水账） |
| `.workbuddy/memory/2026-10-04.md` | 26.5 KB | 292 | 当日进展 |
| `README.md` | **33.5 KB** | 591 | "怎么跑" |
| `docs/使用说明书.md` | **22.7 KB** | 600 | "怎么跑" |
| `docs/全流程流水线-编排手册.md` | **17.8 KB** | 304 | "怎么跑" |
| `config.example.toml` | 17.4 KB | 259 | "配什么" |
| `.work/<task>/manifest.json` | **52.8 KB** | — | "到哪了" |
| `.work/<task>/shots.json` | **516 KB** | — | "这一镜写了什么" |
| `parse.json` | 120 KB | — | "原文是什么" |
| **合计（不含 shots.json）** | **≈ 340 KB ≈ 9 万 token** | | |

**一次"先搞清楚在哪"的续跑 ≈ 10 万 token；其中真正有用的信息大约 500 token。**
（`.work/` 与 `docs/` 还有 5.65 GB / 17.6 MB 的产物与媒体，一旦被 `glob` 命中就是灾难。）

### 8.2 六个根因（按影响排序）

**R1 ✅ 已经有解，但没用起来：`continuation_summary.py` 的输出只有 ~200 token**

`.work/tools/continuation_summary.py` 是项目里**最省 token 的发明**：5 行输出 =
「每任务的图片数 / 门禁开闭 / 下一道门 / 产物就绪 / 最近产物时间」。实测：

```
任务        config                图片     门禁     next      产物            最近
UGE03     config.雨月物语.toml      363    5/6    G2        YYYYYY        10-04 22:54
```

但它的位置和形态都在阻碍它被使用：
① 躺在 `.work/tools/` 里 —— **`.work/` 是 gitignore 的产物目录**，清目录 / 换机器 / 换 clone 就没了；
② 不在 CLI 里，agent 得先 `ls .work/tools` 才知道有它；
③ 实测在 PowerShell 控制台（GBK）下会抛 `UnicodeDecodeError` → **每次续跑先花 token 排障**；
④ README 33.5 KB 里**一个字都没提它**。

→ **修法（最高性价比）**：把它升成 `lvs status --brief`。
```python
# lvs/cli.py · 新增子命令（把 .work/tools/continuation_summary.py 的核心逻辑搬进 lvs/summary.py）
p = sub.add_parser("status", help="一行一任务的状态摘要（续跑第一步跑这个，别读 shots.json）")
p.add_argument("--brief", action="store_true", help="只打 5 行表格（默认）")
p.add_argument("--task", default=None, help="只看这一个任务")
p.add_argument("--all", action="store_true", help="列出全部任务（默认只看 UGE*）")
```
```markdown
<!-- AGENTS.md 开头，替换掉现在的 4 行长说明 -->
## 续跑第一步（唯一入口）

    ./.venv/Scripts/python.exe -m lvs status --brief   # ≈200 token，别读 shots.json / 手册
```

**R2 仓库根 25+ 个调试产物污染检索**（详见 §6.1）
`assets_full.log` 70 KB、`comfyui_restart.log` 122 KB…… 每一次 `ls`、每一次
`glob **/*.log`、每一次"这个文件是什么"都会被读进上下文。**它们的信息量是 0。**
→ ✅ 本次已补 `.gitignore`；⏳ 建议物理搬走 + `lvs doctor` 报数。

**R3 `shots.json` 516 KB，且**没有**廉价的按需读取**
`AGENTS.md` 现在的做法是**禁止**读它（"禁止一上来就 Read shots.json（475KB）"）——
这是对的，但**禁止本身暴露了缺陷**：想知道"第 193 镜提示词写了什么"时，agent 没有别的路，
只能违反禁令去读，或者放弃。
→ **修法**：给"读一镜"和"看索引"各开一个便宜出口：
```bash
python -m lvs shots --task UGE03 --peek 193     # 只打印这一镜（≈300 token）
python -m lvs shots --task UGE03 --index        # 一镜一行：id/时长/来源/提示词首 40 字（516KB → ~30KB）
```
> 这是**结构性修复**：把"要不要读 516 KB"从一个道德问题（别读！）
> 变成一个工程问题（有更便宜的路，自然就没人读大的）。

**R4 当日日志 63 KB / 916 行，是流水账不是索引**
`2026-10-03.md` 单日 916 行。agent 要读完才知道哪条跟当前任务相关。
→ **修法**：日志每段**首行写锚**（`## UGE03 · G2 定妆 · 未批准`），或按任务分文件。
   更省的做法：日志只写"决策与踩坑"，过程细节交给 `lvs status` 和 `runlog.jsonl`（已经有）。

**R5 "怎么跑"有三份 74 KB 的说法，agent 不知道哪份权威**
`README`(33.5) + `使用说明书`(22.7) + `编排手册`(17.8) = 74 KB，说的都是同一件事的三个粒度。
→ **修法**：README 只留「它是什么 + 安装 + 命令表 + 指针」，把"怎么跑"全部收敛到编排手册；
   `AGENTS.md` 里写死一句"要流程 → 只看编排手册"。加 `docs/README.md` 索引（§7.3）。

**R6 报错 → 排障的成本比报错本身高**
本轮真实踩到的：PowerShell 控制台 GBK → `continuation_summary.py` 抛 `UnicodeDecodeError`；
`--timeout` 参数不存在 → pytest 直接 usage error（exit 4），**看起来像测试挂了**；
用 anaconda 的 python 判活会假失败。这些坑全都**只写在 MEMORY.md / 900 行日志里**，
agent 不读就一定会再踩一次。
→ **修法**：`lvs doctor --agent` —— 一次输出 20 行"可复制的环境事实"：
```
解释器      D:\LongVideoStudio\.venv\Scripts\python.exe  (3.11.9)   ← 别用 anaconda
config      D:\LongVideoStudio\config.雨月物语.toml
任务 UGE03  门禁 5/6 开，下一道 G2（定妆） → lvs gate --task UGE03
产物        publish/meta.json 已就绪（22:54）
编码        控制台 UTF-8 未开：跑脚本请加 `-X utf8` + `$env:PYTHONIOENCODING="utf-8"`
下一步      lvs gate --task UGE03 --approve G2 --note "…"
```

### 8.3 量化收益

| 动作 | 续跑起步成本 |
|---|---|
| 现在（读 MEMORY+日志+手册+manifest） | ≈ **9–10 万 token** |
| 做完 R1 + R2 + R5 | ≈ **500 token** |
| 再做完 R3（按需看单镜） | 增量 ≈ 300 token/镜（而不是 13 万 token 全读） |

> **关键认知**：省 token 不是"让 agent 少干活"，而是**让 agent 不必猜**。
> 这个项目已经写出了正确的工具（`continuation_summary.py`）——它只差"进 CLI、进文档、进测试"这三步。

## 10. 整体架构改进建议

### A1. 把 "Stage vs Driver" 两层写进架构文档（本次已实践）

`stage.py` 现在事实上区分了两类东西：

- **Stage**：进 `STAGES` / `ORDER`，有门禁，参与 `lvs run`（`parse`/`shots`/`assets`/`voice`/`build`）。
- **Driver**：进 `DRIVERS`，**有产物但无门禁、不参与 `lvs run`**（`run`/`studio`/**`publish`**）。

这个区分是对的：`publish` 干活要花 0 GPU 钱、产物错了重跑一次 5 秒，**不该**给它加一道门禁挡路。
建议把它**从隐性约定升成显性规则**，写进 `docs/架构审查-整体.md`，并保留现有断言：

```python
# tests/test_architecture.py（已有同类断言，建议再加一条）
def test_drivers_never_enter_the_pipeline_order():
    """Driver 有产物但不走 `lvs run`；一旦混进 ORDER，`lvs run` 会莫名其妙多跑一步。"""
    assert not (set(s.name for s in stage_mod.DRIVERS) & set(stage_mod.ORDER))
```

### A2. 抽 `artifact.atomic_write_text`，让"写产物"只有一条路

现状：`workspace._write_manifest` 独占三段式原子写；其余 **30 处** `.write_text` 各写各的
（`pipeline.py` / `shots.json` / `subtitle.srt` / `build` 的成片……）。
**铁律**：凡"写坏了就得重来"的产物，一律走 `artifact.atomic_write_text()`（代码见 §2.3）。
自查清单：`grep -rn "\.write_text(" lvs/ | grep -v atomic_write` 应只剩**纯日志/短生命周期**文件。

### A3. 加 `cachekey` 模块：凡"跳过/复用"必带参数指纹

这是本项目**最反复踩的一类 bug**，已记录三次：
- voice：换音色残留旧音频（票据 47）→ 加 `voice` 比较；
- voice：改 rate/pitch 仍残留（票据 46）→ **还没修**；
- `norm/*.wav` 不随 mp3 失效 → 加 mtime 比较。

三次都是"同一个错误的不同实例"：**缓存键不全**。建议：

```python
# lvs/cachekey.py
"""凡"跳过/复用"判定，必须带**参数指纹** —— 这是本项目最容易踩的一类 bug。

已踩过的三个实例（都因为没有指纹或指纹不全）：
  ① 换音色残留旧音频（票据 47）  ② 改 rate/pitch 静默沿用旧音频（票据 46）
  ③ norm/*.wav 不随 mp3 失效
判据：凡写 `if 产物存在: 跳过`，先问一句"决定这个产物内容的**全部**参数，
我有没有都算进指纹里？"
"""

def fingerprint(*, params: dict[str, object], inputs: list[Path], impl_version: str = "") -> str:
    """参数 + 输入文件指纹 + 实现版本 的联合签名（少算一项就是一类静默错误）。"""
    from lvs import artifact
    body = "|".join([
        *(f"{k}={params[k]!r}" for k in sorted(params)),
        *artifact.entries(sorted(inputs)),
        impl_version,
    ])
    return artifact.signature(body)
```
> 落到代码：`_audio_reusable()` 改成 `if key_path 的指纹 != cachekey.fingerprint(...)`。
> 同时把 `impl_version` 传进去 —— 提示词模板改了也应该失效（`qc.py` 已有"提示词版本"概念，可复用）。

### A4. 上下文分层（对 agent 友好的目录契约）

```
入口层   AGENTS.md          ≤ 40 行，只写"先跑 lvs status --brief"与禁止事项
约定层   .workbuddy/memory/MEMORY.md   唯一权威，≤ 100 行，只写"必须遵守的约定"
导航层   docs/README.md     ≤ 15 行索引，只写"要办 X → 看 Y"
真相层   docs/编排手册.md   人的操作手册（唯一一份"怎么跑"）
产物层   .work/<task>/      机器产物（含 manifest/publish）；.work/tools/ 里的工具要迁进 lvs/
```
**判据**：任何一层的内容，都不应该需要读下一层才能理解。现在 R1/R5 的问题正是**层界糊了**。

### A5. `doctor` 从"环境体检"升级为"续跑助手"

`lvs doctor` 现在体检 Python/ffmpeg/驱动/密钥（对的）。建议加 `--agent` 模式（§8.2-R6），
输出**可复制的下一步**。它天然是 agent 的第一个调用点 —— 一处做对，每轮都省。

### A6. 建议保留不动的（避免过度重构）

- ✅ `print` 为主的用户提示（不要换 logging）
- ✅ `stage.py` 单一真源
- ✅ 逐镜失败隔离 + 熔断
- ✅ 降级不阻断（BGM/字幕/封面）
- ✅ `workspace._write_manifest` 的原子写（只是要推广，不是要改）
- ✅ 票据驱动开发（`.scratch/`）—— 只要**入库**
