## 二、本轮已修复（都经过实测验证）

### ✅ 修复 1：打包漏了子包 `lvs.gui`

**修前**（实测）：

```
$ pip wheel . --no-deps
总文件数: 46 ｜ gui 文件数: 0 ｜ ★ 缺失
```

`pyproject.toml` 写死 `packages = ["lvs"]`，而 `find_packages()` 能找到 `['lvs', 'lvs.gui']`。

**修后**：

```toml
[tool.setuptools.packages.find]
include = ["lvs*"]

[tool.setuptools.package-data]
"lvs" = ["../workflows/*.json"]     # 生图模板是运行时数据，必须打进去
```

**验证**（实测）：

```
$ pip wheel . --no-deps
总文件数: 55 ｜ gui 文件数: 5 → ✓ 已包含 ｜ workflows: 3 ✓
```

### ✅ 修复 2：装完之后能用（这是原本的"隐忧"）

原先担心 `PROJECT_ROOT = Path(__file__).parent.parent` 在装到 `site-packages` 后会失效。
**实测结论：修完打包后可以正常工作** ——

```
装到临时目录，从**非仓库目录**导入：
  lvs 包位置: …/inst/lvs/__init__.py
  PROJECT_ROOT = …/inst                    ← 就是 site-packages
  workflows 目录存在: True                  ← 模板随包安装
  imagegen 找模板: True
  全部模块可导入（含 lvs.gui）✓
  入口点 lvs --version → lvs 0.1.0 ✓
```

再加一条：**用户用自己的 `config.toml`** —— 实测 `find_config()` 会**优先读工作目录**，
所以"在任意目录建个项目文件夹、放一份 config.toml"这个用法是成立的。

> 结论：**两种使用方式都成立**（克隆开发 / `pip install`），README 已同时写明。

### ✅ 顺手修的两个真 bug

1. **`doctor` 不认识 `silent` 后端** —— 我上一轮加了离线后端却没更新体检，
   于是体检对着一个**完全正常**的配置报"未知后端"，误导用户去查不存在的问题。
   修法不只是改那一处：加了 `SUPPORTED_BACKENDS` 作**唯一真源**，`doctor` 与报错信息都从它取。
2. **素材库未命中时，报错看不懂** —— `--source library` 没命中会静默回退去调 ComfyUI，
   然后报"ComfyUI 不可达"；用户明明只配了图片文件夹，完全不知道真正原因是"关键词没匹配上"。
   现在会说清因果，并给出两条具体出路（改图片名 / 配 LLM key）。
