**关键判断：讲书口播的AI味 ≠ 书面文的AI味。**

## 续：第一章音画事故定案与修复（20:20）

用户反馈：「第一个视频严重字幕语音不对 → 按第二章标准重做第一章 → 继续做下去」。

### 一、根因（**不是字幕对齐算法的问题**）

三个时长对不上：

| 产物 | 时长 |
|---|---|
| `NW01P1/audio/narration.mp3` | 1100.83s |
| `NW01P1/subtitle.srt` 跨度 | 1167.9s |
| `NW01P1/video-track.mp4` | 1168.87s |
| 成片 `final.mp4` | 1103.23s（被 `-shortest` 截断） |

逐层实测后定位：`audio/norm/*.wav`（**拼接真正用的那一套**，见 `concat.txt`）
与 `shot-*.mp3` 完全不是一代产物。

| 套 | 60 镜合计 |
|---|---|
| `norm/shot-001..060.wav` | **1083.07s** ← 1083.07 + 59×0.3 = 1100.77 ≈ 整轨 ✓ |
| `shot-001..060.mp3` | **1151.18s** ← 1151.18 + 17.7 = 1168.88 = 画面轨/字幕轴 ✓ |

`norm/` 里还躺着 **shot-061..066**（上一版的镜数）→ 铁证：`norm/` 是上一版残留。

**机制**：TTS 参数变更后重跑 `lvs voice`，`mp3` 按文本 hash 判定重建，
`norm/*.wav` 的跳过判定**没跟着失效** → 拼接用旧 wav（旧音色、旧时长），
`shots.json` 时间轴按新 mp3 → `build` 出 1168.87s 画面轨、1100.83s 音轨，
`-shortest` 截掉结尾 65s，**并从丢镜处开始整体漂移**。
顺带解释了用户早先说的"声音苍老"——听到的本来就是旧 wav。

### 二、修复

```bash
mv .work/NW01P1/audio .work/NW01P1/audio.stale-<ts>   # 整目录移走（关键：别只删 mp3）
.venv/Scripts/python.exe -m lvs voice --task NW01P1 --force
.venv/Scripts/python.exe -m lvs build --task NW01P1
```

结果：**画面轨 1168.87s｜旁白 1168.95s｜成片 1168.87s｜偏差 0.08s**（第二章为 0.06s，同档）。
已交付 `07-成片/001-开篇即结局-第一章.mp4`（433 MB）+ `.srt`。

**方法论**：判「音画同步」只比 `final.mp4` 与 `audio` 的总时长**不够**——
必须查 `Σshot 音频 + (n-1)×gap` 是否等于 `video-track` 时长；
不等就是缓存代际错位，重跑 voice 也未必能修（除非清 `norm/`）。
