# Ollama 可承接环节调研（2026-10-05，纯静态分析）

> 只出建议，不改代码、不启动 ollama/TTS。方法是读代码（`lvs map show/grep`）+ 已有路由表，不实跑。
> 前提认知：**本机只有 3 个真实 LLM 接入点**（下 §现状），切不切本地是在"整条 site"上翻开关，不是在子任务上切。

## 一、现状：路由真源与真实调用点

- 路由真源 `lvs/llm_provider.py`：`DEFAULT_ROUTES = {bgm.style: local, publish.meta: local, assets.tagging: local, shots.beats: remote, shots.prompts: remote}`，未登记的一律 `remote`（保守默认）。
- 总开关 `LVS_LLM_PROVIDER` 环境变量 > `[providers].mode`（auto/local/remote）> 默认 `auto`；单点覆盖走 `[providers.routes]`（键名带引号）。
- 本地腿：`base_url=http://localhost:11434/v1`，`model=qwen2.5:7b-instruct-q4_K_M`，ollama **CPU 推理**（`OLLAMA_LLM_LIBRARY=cpu`），不吃 8GB 显存（与 ComfyUI/TTS 不抢 VRAM，但吃 CPU/内存、加墙钟）。
- 生产调用点实测（`grep LLMClient.from_config`）**只有 3 处**：
  1. `lvs/bgm.py:373` site=`bgm.style`（已本地）
  2. `lvs/publish.py:677` site=`publish.meta`（已本地，仅 `--llm` 时）
  3. `lvs/shots.py:975` site=`shots.beats`（远程；**同一个 client 覆盖 6 个子任务**：beat 归位 / kind 分类 / scene 翻译 / prompt 生成 / keywords / source 判定；`shots.py:1043` 的 `_llm_fix_negations` 否定式改写也复用这个 client）
- `assets.tagging` 已登记为 local 但**全仓无调用点**（占位）。
- 无 LLM 的环节（纯规则/启发式）：`check.py`（拍摄稿格式校验，纯函数）、`cast.py`（`parse_card` 正则 + `ANCHOR_RULES` lint）、`migrate.py`（正则补标注 + 代词映射，否定句列清单交人）、`parse.py`（规则 + `uncertain` 清单交人）、`prompting.classify/resolve_kind`（关键词）、`qc.py`（图像规则：黑边/彩度/人数/提示词版本）、`assets.py`（Pexels/ComfyUI，只做 `{NAME}` 槽位替换）、`tts.py`（faster-whisper 对齐，非 LLM）。

## 三、Ollama 承接优先级清单（给用户拍板）

### 建议切
1. **提示词否定式改写**（`shots.negations` 新 site，默认 local）。理由：局部改写、任务是"把否定句改成正面物理陈述"，7B 完全够用；`prompt_negations` 改写后复检兜底，失败只掉一点质量；省下的是每次拆镜都要付的一段远程 token。
   - 前置：`shots.py` 现在只建一次 client（site=`shots.beats`），切它必须先拆出独立 site —— 属 P3 目录/接线改造，现在**不要动**。

### 可试点（只报警、不影响门禁，用 `[providers.routes]` 单点覆盖即可试）
2. **字幕/对白校对**（新 site `voice.subtitle`）：保时间码只改文本，失败原样保留；先在小任务上人眼比对误改率。
3. **分镜质量抽检**（新 site `shots.qc`）：文本层读 `shots.json` 抽检，只报警，与 `qc.py` 图像规则互补。
4. **剧情/人物一致性（文本层）**（新 site `cast.consistency`）：只报警，交人判；图像层一致性仍靠 cast lock + 参考图，不指望 LLM。

### 不建议
5. **拆镜 beat 归位 / 逐镜提示词整条切本地**：质量核心，7B CPU 在 363 镜的稿子上既慢又掉点，省 token 不值这个风险。
6. **讲稿润色/事实纠错**：改语义 = 改内容，版权/事实风险高；`check.py` 规则已够定位。
7. **历史/地理/专名查证**：幻觉会进成片文案，应用检索（工具查证）而非生成。
8. **多轮剪辑决策建议**：G5 是人的事（`criteria.py` 刻意不设 G5 判据）。
9. **文本分类/摘要、元数据补全**：前者与拆镜 kind 分类重复，后者已走本地。

## 四、约束与前提（拍板前须知）

- ollama 是 **CPU 推理**：不抢 ComfyUI/TTS 的 8GB 显存，但**加墙钟**；流水线串行，拆镜阶段同时跑本地 LLM 会明显拖慢。
- `[providers.routes]` 目前**切不动 `shots.prompts`**：该 site 虽已登记，但 `from_config` 只在 `shots.beats` 上调过，两处共用同一 client（源码注释已言明）。
- 一键回滚：`LVS_LLM_PROVIDER=remote`（或 `[providers].mode="remote"`）回到 P2 之前现状，一字不差。
- "LLM 配没配"仍由**远程 key** 决定（`llm.available()`）；只有 `mode="local"` 才允许无 key 直接走 ollama。
- 落地任一"新 site"都要改 `lvs/llm_provider.py` 的 `DEFAULT_ROUTES` + 调用方 `from_config(site=...)`，属 P3 范围（本调研**不动代码**）。
