# 30: 手动向导 `lvs studio` —— 与全自动并存的检查点式流程

**What to build:** 把「素材获取」拆成**有检查点的手动流程**，让"图我要一张张看"这件事变得可行；
`lvs run` 的全自动一键到底**原样保留**，两条路互不干扰。

**Blocked by:** 24, 27, 28

**Status:** done

**背景（用户诉求）**：用户先上传拍摄稿，希望流水线**停下问**——
「这次是下载实拍素材 / 本地生图 / 翻已有素材库？」
出图完成后**再停一次**：「继续下一步（配音 → 合成），还是先改几张图？」
即"素材这一段"要能一步步确认，而不是跑完才看到结果。

---

## 设计：一条向导，两种用法

每个提问都对应一个参数，所以同一个 `lvs studio` 既是**交互向导**，也是**可脚本化**的一步：

| 提问 | 参数 | 非交互默认 |
|---|---|---|
| 拍摄稿路径 | 位置参数 / `--manuscript` | 沿用上次解析的源，否则报错 |
| 取哪些素材 | `--action pexels,local,graphic,library` / `all` | **报错**（不静默） |
| 素材后走向 | `--stop` / `--redo` | `--yes` 时自动 `continue` |
| 改哪些镜 | `--redo 1-10,15` | — |
| 换提示词 | `--prompt "..."` | — |
| 换种子 | `--seed N` | 未给且未改词 → `seed+1` 重抽 |

- **非交互终端 + 不给参数 → 直接 `StudioError` 报错**，绝不挂在那里等输入（`_ask` 里查 `isatty`）。
- `--yes` = 「全部选是」：`action=all`、看完素材直接 `continue`。适合批处理。

## 关键实现点（都踩过坑）

- [x] `_prepare` 先跑 **parse → shots**（幂等：同一份稿 + 产物在就跳过）
- [x] `assets` 增 `--only`：只跑选中的分支（`assets.only_matches`），不再全分支乱跑
- [x] **`route_pexels_to_local`**：选了「生图」却没选「下载素材」时，
      把 `source=pexels` 的镜**改成 `local`**——否则这些镜永远缺素材。
      （这是第一次干跑发现的漏洞：只看 `--only` 会漏掉 intent 冲突）
- [x] **`clear_shot_assets` 连片段一起删**：片段缓存只看时长，
      图换了但时长没变会被原样复用；所以图 + 片段 + `asset_path`/`library_asset` 一起清，
      状态回 `pending`
- [x] `redo_shots` 支持**只改词**（`--prompt`）、**只换种**（`--seed`）、**都没有则 seed+1**
      —— 连续重抽会一直往前走，不会原地打转
- [x] `--stop` 停下时打印**续跑命令**：`lvs studio --task NAME`（已完成阶段自动跳过）
- [x] 分支标签中文化：下载实拍素材 / 本地生图 / 图文卡片 / 翻已有素材库
