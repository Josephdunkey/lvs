# 36 · 本地 GUI（`lvs gui`）

**Status:** done
**关联**：D2（改写）、D14、D15、D22、D26、spec §9/§11/§13
**取代**：`CONTEXT.md` 里「D2 本期不做 GUI」这句话

## 起因

用户要一个图形界面：建任务、跑阶段、看进度、**按镜审片重做**、预览成片。
同时提了两个开放选项：「如果能直接用 ComfyUI 改也行」「做好看点」。

## 用 grill 把分支走完（结论）

| 分支 | 结论 |
|---|---|
| 落在哪 | **仓库内独立本地 Web 应用**（`lvs gui`），不是 ComfyUI 扩展。理由：ComfyUI 前端扩展只覆盖「本地生图」这一段（五阶段里的一段），且必须先开着 ComfyUI；TTS/合成本来就与它无关 |
| 怎么驱动 | **子进程调 `python -m lvs <阶段>`**，一行 lvs 代码不改；进度**数盘上已落盘的逐镜产物**（与进度条同一个 done/total），日志收 stdout；阶段状态以 manifest 为准（D15） |
| 写权限 | **只写 `.work/<task>/`**；`config.toml` 只读展示 + 校验；素材库只读（D13） |
| 生命周期 | 阶段跑在独立子进程，**关掉浏览器/服务不影响它**；**全局串行**（8GB 显存，spec §11） |
| 前端栈 | Jinja + 原生 JS + SSE，**零构建、零 node_modules** |
| 观感 | 墨色 + 朱砂，但按**密集工具**组织：黑体承载界面文字，宋体只留给标题与数字 |
| 卡面样式 | 只做 `graphic/photo` 开关（不引入卡片主题系统） |
| 镜能改什么 | `prompt / seed / source / narration` —— 直接写 `shots.json`（人工可编辑的真相源，D14） |
| 素材库页面 | 只读：扫描 + 看 + 搜，不删不移（D13） |
| v1 验收 | **全程不碰终端**跑通一个真任务 |

**为什么没做成 ComfyUI 扩展**：显存约束（D-1/§11）与串行编排是整条链的事，不是 ComfyUI 的事；
而且界面要能建任务、跑 TTS、合成、审片 —— 这些塞进画布式 UI 里只会更别扭。ComfyUI 仍是被调用的一个后端。

```
lvs/gui/static/     app.css（墨色+朱砂设计系统）/ app.js / task.js

```

### 36.1 一个必须记住的坑：进度不能读 `shots.json`

`assets` / `voice` / `build` **只在阶段跑完时才写 `shots.json`**。若照直觉去读它的 `status`，
进度会在 0% 卡到阶段结束 —— 界面看起来像死了。所以进度一律**数盘上已落盘的逐镜产物**：

```
assets  →  assets/{library,pexels,local,graphic}/shot-NNN.*   去重后的 stem 数
voice   →  audio/shot-NNN.*        （narration.mp3 是整轨，不算）
build   →  segments/shot-NNN.mp4   （concat.txt 是辅助文件，不算）
```

这条同时给了"聚合文件不算进度"的判据，已写成测试。

### 36.2 安全边界都落到了测试里

- **任务名钉死在 `.work` 内**：`task_dir("../..")` → `None`；`slugify` 在写盘前规整。
- **产物服务防越界**：`../../config.toml`、`..%2F..%2F`、`..%5C..%5C`、`/etc/passwd` 一律取不到
  （断言"永不返回 200"，把重定向也算进去）。
- **argv 不用 shell**：任务名带 `;` 也只会被原样当参数；自由文本参数（`--prompt` 要收中文）
  只挡控制字符与超长，不做字符白名单。
- **密钥遮蔽**：设置页把 `*key/*token/*secret/*password` 显示成 `abcd…wxyz`。
- **配置只读**：设置页只有展示与校验，没有任何写入口。

### 36.3 顺手消掉的两处重复

- `doctor.run()` 里的体检项清单抽成 `doctor.all_checks(config)`，CLI 与 GUI 共用一份，免得漂移。
- `Config` 补了一个 `as_dict()` 只读快照 —— 设置页要摊平展示，`_data` 是私有的，
  与其在界面里伸手进去，不如开一个诚实的只读口。

### 踩到的两个坑（都已修/已记）

**坑一：验收脚本自己漏看退出码。** 第一次跑，重做那步 `wait_idle()` 只等"阶段不忙了"，
于是**失败的 job（rc=1）被当成成功**，脚本只说"图没变"，给不出原因。
这跟 D23 是同一个教训的另一面：**进度条证明不了成功，退出码才能**。
已改成等空闲后回读该 job 的日志、见"退出码/启动失败"就抛错并附日志尾部。

**坑二（环境，非产品）**：在**沙箱会话**里驱动界面时，`--redo` 会被宿主的
**删除量钩子**拦下：

```
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":295,"threshold":50,"scope":"turn",…}
```

`--redo` 按设计要**删掉旧素材与已合成片段**（否则片段缓存只看时长，换了图会被复用，票 30），
所以它必然触发删除守卫。这是**按轮次累计**的计数，重启服务也没用。
在用户自己的终端里没有这个钩子 —— 同一条命令手工跑**成功**：

```
lvs studio --task gui-e2e --redo 2 --active local --yes   → rc=0，「新取 1」
  · shots.json 里 shot 2 的 seed: None → 45
  · assets/local/shot-002.png  75836b57… → 2ee67f45…（真的换了图）
  · .thumbs/shot-002.jpg       5c948780… → 3ddac6bc…（缩略图缓存自动失效 ✓）
```

**这条要记住**：界面要能重出图，就必须有权删任务目录里的文件。
把它关在"只读沙箱"里时，失败会**诚实地出现在日志面板**里（这点是对的），
但要在无钩子的终端里跑 `lvs gui` 才能真正用起来。
