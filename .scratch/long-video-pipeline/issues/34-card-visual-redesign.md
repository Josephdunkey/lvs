# 34 · 图文卡片视觉重做（HTML/CSS 渲染）

**Status:** done
**关联**：票 28（卡片渲染器）、票 31（卡片正文与边框溢出）、D20/D24、票 35

## 起因

用户在小样成片里看到卡片，给出两条意见：

1. **"这些 png 太丑啦"**；
2. **"不要什么第一段第二段种种脚本提示词进去"**。

第 2 条是**事实**：`assets.py` 的 graphic 分支把 `shot["segment_heading"]` 当 `title`
传给渲染器，于是每张卡正上方都印着 `第一段 · 钩子落定` / `第二段 · 前提：名分这个东西…`
—— 那是拍摄稿的编辑脚手架，不是内容。

第 1 条顺着查下去，根因是**没有构图**：一张 1920×1080 里只有「顶部一行小字 + 居中一段话 +
右下角 28px 小字 + 一个 2px 方框」，其余 80% 是空的。Pillow 手画也很难做出层次
（没有渐变/阴影/真字重对比/网格）。

## 决策（用户四选）

| 项 | 选择 |
|---|---|
| 视觉方向 | **A 的底子 + C 的结构**：墨色宋体气质，配规整数据面板；不做印章、不做竹简竖纹 |
| 页脚旁白 | **去掉**（成片底部已烧同一条字幕，重复且会撞边框） |
| 内容层 | **顺带一起修**（→ 票 35） |
| 渲染方式 | **改 HTML/CSS**（无头浏览器截图），并保留 Pillow 回退 |

三套样张（A 竹简朱墨 / B 墨金 / C 靛青信息图，各 2 张）用真实内容渲出后交用户选。

## 做了什么

### 34.1 新增 `lvs/cardhtml.py` —— HTML/CSS 出图
- 用**本机已装的无头浏览器**（Edge/Chrome）截图 1920×1080，不新增任何 Python 依赖：
  `--headless=new --screenshot=… --window-size=1920,1080`，独立 `--user-data-dir` 避免污染用户配置。
- 浏览器探测：`LVS_BROWSER` 环境变量 → 各平台常见安装路径 → `shutil.which`。
- **必须用绝对路径**：浏览器解析 `--screenshot=` 用的是它自己的 CWD，相对路径会被丢掉
  （实测踩到，已修 + 回归测试 `test_accepts_relative_path`）。
- 浏览器先退出、后落盘有竞态 → 截图后轮询确认文件真的出现，失败再重试一次。

### 34.2 版式：4 套（statement / compare / timeline / list）
原来 5 套（timeline/numbers/columns/flow/card）语义重叠，收成 4 套并交给 `cards.layout_of` 一处判定。
视觉语汇统一：**朱砂红短竖线 = 唯一的强调方式**（statement 的每项、compare 的主面板、list 的每行），
圆角统一 12px，面板只用 1px 细边 + 极浅底色。

### 34.3 字号自适应交给浏览器实测
一开始用 Python 估宽算字号，**估错了**：漏算 `.datum` 的 36px 内边距，三个数值挤到第二行，
右边留一大片空。改为**页内脚本自己量**（`data-fitbox` / `data-fitcell` / `data-shrink`），
任何版式都不会溢出或折行。少了一个必然估不准的估算器。

### 34.4 `graphic.py` 收口成调度器
`render(card, out_path)`：优先 HTML，无浏览器/截图失败则回退 Pillow。两条路的输入是**同一个
`cards.Card`**，所以内容逻辑只有一份，换渲染器不会让卡上出现的东西变样。
`GraphicError = cardhtml.CardError`，调用方仍只需一个异常类型。

### 34.5 Pillow 版式同步去掉标题与页脚
回退路径也要守同一条规矩，否则"没装浏览器"就等于把脚本脚手架又请回来了。

## 验证

- 数据行**不再折行**：内容 bbox 单行带，左右边距 150px（正好等于设计留白），无溢出。
- 5 条真实 beat 出 5 张卡：`kind` / `items` / `source` 全部符合预期。
- 测试：244 → **281**（新增 `test_cards.py` 26 项、`test_cardhtml.py` 12 项、重写 `test_graphic.py`）。

但"好不好看"需要用户看完成片再给意见。
